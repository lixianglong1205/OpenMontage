# 入门引导 — 元技能

## 何时使用

在新会话中与用户的**第一次交互**时，若用户尚未给出具体的制作请求——或其请求很模糊（例如「帮我做个视频」「你能做什么？」「帮我创作点什么」）——则使用本技能。

当用户带着明确、可执行的请求而来时（例如「做一个 60 秒的黑洞科普讲解视频」），跳过本技能，直接进入规则零（识别流水线 → 预检 → 执行）。用户已经清楚自己要什么。

**本技能将智能体从被动执行者转变为创作伙伴。** 多数用户并不清楚能做什么。你的任务是用清晰、快速的方式展示能力，并提供可立即复制粘贴的示例提示。

## 流程

### 步骤 1：运行预检发现

在输出任何创意内容之前，先弄清当前环境具备什么：

```bash
python -c "
from tools.tool_registry import registry
import json
registry.discover()
envelope = registry.support_envelope()
menu = registry.provider_menu()
print('=== ENVELOPE ===')
print(json.dumps(envelope, indent=2))
print('=== MENU ===')
print(json.dumps(menu, indent=2))
"
```

将输出解析为三类：

1. **可用** — `status: AVAILABLE` 的工具
2. **快速解锁** — `status: UNAVAILABLE` 且 `install_instructions` 指向环境变量（约 1 分钟可修复）的工具
3. **硬件解锁** — 需要 GPU 或本地模型下载的工具

### 步骤 2：判定用户的配置层级

根据发现结果，将环境归类为：

| 层级 | 可用能力 | 最佳流水线 |
|------|-----------------|----------------|
| **零密钥** | Piper TTS + Pexels/Pixabay 素材（若已配置密钥）+ Remotion 和/或 HyperFrames + FFmpeg | 动画讲解（素材画面 + 免费旁白） |
| **入门** | 已配置一家图像生成提供商 + 免费 TTS + Remotion 和/或 HyperFrames | 动画讲解、动画（AI 生成画面） |
| **标准** | 图像生成 + TTS + 音乐生成 | 动画讲解、动画、屏幕演示、混合 |
| **完整** | 视频生成 + 图像生成 + 高级 TTS + 音乐 | 全部流水线，含电影感、数字人、口播 |
| **完整 + GPU** | 云端 API + 本地视频生成模型 | 全部流水线，并含免费本地回退 |

**合成运行时** — 二者均为一等公民，在提供商菜单中分别展示。请分别报告各自可用性：

- **Remotion** 需要 Node.js + `npx` + `remotion-composer/` + `node_modules`。
  适合基于 React 的场景组件（文字卡片、数据卡片、图表）、
  词级字幕，以及 `TalkingHead` 数字人合成。
- **HyperFrames** 需要 Node.js ≥ 22 + `npx` + FFmpeg。通过
  `npx @hyperframes/cli` 使用（无需检出 monorepo）。
  适合 HTML/CSS/GSAP 动效 —  kinetic  typography、产品宣传片、
  发布短片、网站转视频工作流、registry 区块。

在「即可使用」摘要中，若两者皆可用，**须明确写出两种运行时名称** —
不要只写「Remotion」。新会话中若未点名 HyperFrames，提案阶段往往
不会呈现它；在此命名可建立「智能体与运行时无关」的预期。

若仅有一种可用，在摘要中说明，并提及另一种将解锁什么。若皆不可用，
告知用户当前仅有 FFmpeg（简单拼接/裁剪），以及解锁 HTML/React
合成需要什么。

**入门引导阶段不要选定运行时。** 运行时选择在提案阶段进行，
即在智能体理解简报之后。入门阶段只报告能力，不做制作决策。
见 `AGENT_GUIDE.md` →「Present Both Composition Runtimes (HARD RULE)」。

### 步骤 3：问候与定向

给出**简短、友好的能力摘要**。不要倾倒原始提供商菜单，而是用通俗语言转述。

**模板（按实际发现结果调整）：**

---

**欢迎使用 OpenMontage！** 我是你的视频制作智能体。在当前配置下我能做这些事：

**即可使用：**
- [用 2–4 条通俗语言列出关键能力，例如：「用免费离线 TTS（Piper）生成旁白」「用 Remotion 制作带动效过渡、字幕与图表的动画视频」「从 Pexels 获取素材视频与图片」]

**可用流水线：** [列出与其配置匹配的流水线，每条一行说明]

**快速升级：** [若适用 — 根据缺失能力与实际 `install_instructions` 从 `provider_menu()` 中概括最佳 1–2 项解锁。不要硬编码 `FAL_KEY` 或任何提供商为默认建议。]

---

**展示规则：**
- 先说**能做什么**，而非缺什么。让用户感到有力量，而非不足。
- 控制在 8–12 行以内，避免信息过载。
- 最多提及 2 条快速解锁建议，不要罗列每个缺失密钥。
- 从 registry 读取真实 `install_instructions` — 不要硬编码提供商名或密钥名。

### 步骤 4：提供入门提示

根据用户层级，给出 **3 条可直接复制使用的提示**。这些提示应与其具体配置匹配，并能产出令人印象深刻的结果。

**零密钥提示：**

> **现在就试：**「做一个 45 秒的动画科普，讲天空为什么是蓝色」
>
> 我会调研主题、写脚本、找素材画面、用 Piper 生成旁白，并合成带动效与字幕的动画视频 — 全部免费。

> **也可以试：**「我有一段仪表盘操作的录屏 — 做成带字幕和旁白的 polished 产品演示」*（Screen Demo 流水线）*

> **或者：**「把这段访谈录音剪成 3 条适合 TikTok 和 YouTube Shorts 的短视频」*（Clip Factory 流水线）*

**入门层级提示（已有图像生成）：**

> **试试：**「做一个关于 CRISPR 基因编辑如何运作的动画讲解，画面用 AI 生成」
>
> 我会用你配置的图像生成器为每个场景定制画面 — 比纯素材更有视觉冲击力。

> **也可以试：**「做一条关于城市养蜂的短纪录片风格视频 — 要 grounded、有质感，不要 flashy」*（Hybrid 流水线 — 源素材 + 生成辅助）*

> **或者：**「做一条面向八年级学生的光合作用课堂视频 — 简单、清晰、有趣」*（Explainer 流水线 — 教师模式）*

**完整层级提示（已有视频生成）：**

> **试试：**「为科幻概念做一个 30 秒电影感预告：人类收到来自一千年后的警告」
>
> 我会生成真实动态视频片段、合成配乐，并交付成片级电影预告。*（Cinematic 流水线）*

> **也可以试：**「做一个 60 秒数字人发言人视频，宣布公司品牌重塑」*（Avatar Spokesperson 流水线）*

> **或者：**「我用 webcam 录了创始人更新 — 做得 polished、自信、高级，但别显得假」*（Talking Head 流水线）*

**参考类提示（所有层级）：**

> **有喜欢的视频？** 粘贴 YouTube 链接并说「帮我做类似这种的」
> — 我会分析风格、节奏与结构，再提出 2–3 个创意变体供你选择。
> 支持 YouTube、Shorts、Instagram Reels、TikTok。
> 分析在本地免费完成 — 无需 API 密钥。

> **有自己的素材？** 拖入视频文件并说「我想用这段素材做视频」
> — 我会转写、检测场景，并给出剪辑方案。

**提示建议规则：**
- 恰好提供 3 条提示。
- 第一条应是其配置能产出的最 impressive 作品。
- 每条应对准不同流水线或风格。
- 附简短说明，解释为何适合其配置。
- 使用引用块格式，便于区分与复制。
- 始终包含上述参考类提示 — 各层级均适用。

### 步骤 5：简要说明工作流

在提示之后，用 2–3 句话概括用户开始后会怎样：

「你给出提示后，我会先用实时网页搜索调研主题，再向你展示概念选项与费用估算。你选定偏好后，我会分阶段制作视频 — 在每个创意决策处征求你的确认。成片位于 `projects/<name>/renders/`。」

此处不要解释完整架构、三层知识体系或流水线内部细节。那是给好奇者看的 — 若他们想深入了解，指向 `AGENT_GUIDE.md`。

### 步骤 6：处理后续问题

常见问题及回应方式：

**「要花多少钱？」**
- 零密钥路径：$0
- 配置一家付费图像/视频提供商：通常每条视频约 $0.30–$1.50，视素材数量而定
- 完整配置：多数视频约 $1–$3
- 始终说明：「在产生任何费用之前，我会给出精确估算。」

**「能做 [某类具体视频] 吗？」**
- 匹配到一条流水线。若契合，说明用哪条流水线及哪些工具。
- 若无流水线完全匹配，如实说明 — 建议最接近的方案并解释差异。

**「要多久？」**
- 讲解（零密钥）：5–15 分钟
- 讲解（含图像生成）：10–20 分钟
- 电影感（含视频生成）：20–40 分钟
- 「大部分时间花在素材生成上。调研与脚本阶段很快。」

**「我只想快速试一下」**
- 建议最短的零密钥提示：「试试：『做一个 30 秒科普，讲叶子为什么变色。』会用免费工具，大约 5 分钟完成。」

**「展示一下你能做什么」**
- 指向 README 中的演示视频，再提供步骤 4 的入门提示。

## 反模式

- **不要向用户倾倒** `support_envelope()` 或 `provider_menu()` 的原始 JSON。用通俗语言转述。
- **不要罗列每个工具。** 按能力分组（「我可以用 FLUX 生成图像」，而非「我有 flux_image、google_imagen、openai_image、recraft_image…」）。
- **除非被问，不要解释架构。** 「Agent-first、instruction-driven」对开发者有趣，但用户是来拍视频的，不是来读代码库的。
- **不要为缺失能力道歉。** 表述为「这是你已有的」并可选择「这是一步快速升级」。绝不说「可惜你没有…」
- **若用户显得不确定或仍在探索，不要直接开拍。** 花 30 秒定向 — 能避免之后 10 分钟的困惑。
- **不要建议需要用户尚未具备的工具才能完成的提示。** 每条提示必须在其当前配置下可达成。若需特定密钥，须明确标注。
