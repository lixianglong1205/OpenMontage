# Asset Director - Podcast Repurpose Pipeline

## 何时使用

本阶段为播客衍生视频资产构建可复用素材包：字幕、讲者卡片、引用卡片、可选主题配图，以及可选音乐支持。

## 前提条件

| 层级 | 资源 | 用途 |
|-------|----------|---------|
| Schema | `schemas/artifacts/asset_manifest.schema.json` | 产物校验 |
| 前置产物 | `state.artifacts["scene_plan"]["scene_plan"]`, `state.artifacts["script"]["script"]`, `state.artifacts["idea"]["brief"]` | 交付计划与文稿事实依据 |
| 工具 | `subtitle_gen`, `image_selector`, `diagram_gen`, `music_gen`, `audio_enhance` | 资产生成 |
| Playbook | 当前启用的风格 playbook | 品牌一致性 |

## 流程

### 1. 从必选资产开始

最高优先级：

- 每个片段的字幕，
- 在需要时处理干净音频，
- 若出现多位讲者则准备讲者归属资产，
- 面向引用类输出的引用卡片模板。

### 1b. 主场景样片（必选）

在批量生成资产之前：
1. 确定主片段（批次中最重要或最有冲击力的片段）
2. 为该片段生成一份样例资产（字幕样式、讲者卡片或引用卡片）
3. 呈现给用户：「这是最重要片段的视觉方向。是否符合你的设想？其余内容将按此风格生成。」
4. 在继续批量生成前等待用户确认

这可避免最昂贵的错误：按用户不认可的方向生成 10+ 份资产。

### 2. 将主题配图视为可选

生成类图形应支撑批次，而非喧宾夺主。仅在以下情况使用：

- 主题确实需要一张澄清性配图，
- 单集 companion 需要章节分隔，
- 预算能支撑风格一致的输出。

### 3. 使用模板，而非每次重造

优先对以下项使用可复用模板：

- 讲者卡片，
- 引用卡片，
- 片尾卡片，
- 品牌容器。

### 4. 在元数据中保存完整的资产事实

推荐的 metadata 键：

- `speaker_assets`
- `subtitle_assets`
- `quote_card_assets`
- `topic_graphics`
- `music_assets`

### 5. 质量门禁

- 所有片段具备字幕资产，
- 讲者身份在视觉上保持一致，
- 引用卡片文字在移动端仍可读，
- 可选生成类配图保持在预算与风格约束内。

### 制作过程中的事实核查

若在资产生成中遇到不确定之处：
- 使用 `web_search` 核查主体视觉准确性（例如：该建筑实际长什么样？）
- 在生成插图前使用 `web_search` 查找参考图
- 在决策日志中记录：`category="visual_accuracy_check"`

视觉准确性很重要。若文稿提到具体地点、人物或物体，
在生成图像前先核实其真实外观。不要依赖
AI 模型的训练数据——可能错误或过时。

## 常见陷阱

- 在字幕与归属类资产完成前，把预算花在可选配图上。
- 同一单集内讲者卡片风格不一致。
- 为长篇 companion 视频过度产出主题配图。


## 当你不确定做法时

若遇到不确定的生成技法、供应商行为或提示模式：

1. **搜索网络** 获取当前最佳实践——模型与 API 变化频繁，智能体的训练数据可能已过时
2. **查阅 `.agents/skills/`** 中已有的 Layer 3 知识（供应商专用提示指南、API 模式）
3. **若仍无法解决**，在项目目录 `projects/<project-name>/skills/<name>.md` 撰写项目级 skill，记录所学内容
4. **在 skill 中引用来源 URL**，使知识可追溯
5. **写入决策日志**：`category: "capability_extension"`, `subject: "learned technique: <name>"`

以下场景尤其重要：
- **视频生成提示**——模型随版本变化而响应特定词汇
- **图像模型参数**——FLUX、GPT Image、Imagen 等的最优设置各不相同且持续演进
- **音频供应商特性**——声音克隆、音乐生成与 TTS 各有模型级最佳实践
- **Remotion 组件模式**——框架演进中不断出现新的合成技法

不要依赖过时知识。有疑问时，先搜索。

## 门禁提醒（具有约束力）

本阶段以人工审批为门禁（`human_approval_default: true`）。审查通过后：
以 `status="awaiting_human"` 做 checkpoint，呈现摘要（Backlot 看板会渲染
产物），并**结束本轮回复**。勿在同一回复中启动下一阶段。
审批按门禁逐次进行——此前「继续」的指令不覆盖本门禁。
