# Script Director（脚本导演）- 播客再利用流水线

## 何时使用

本阶段创建逐字稿事实依据、说话人归属、高光片段集合与章节结构，后续各阶段均依赖这些内容。

## 前提条件

| 层级 | 资源 | 用途 |
|-------|----------|---------|
| Schema | `schemas/artifacts/script.schema.json` | 产物校验 |
| 前置产物 | `state.artifacts["idea"]["brief"]` | 交付物组合与来源事实 |
| 工具 | `transcriber`, `audio_enhance` | 带说话人分离的逐字稿与音频清理 |

## 流程

### 1. 保障逐字稿质量

若源音频质量较差，在转写之前或与之并行使用 `audio_enhance`。说话人分离（diarization）质量直接影响引语归属与片段质量。

### 2. 产出带说话人信息的逐字稿

多说话人节目必须做说话人分离，不可省略。尽早核对说话人映射，并将更丰富的分离细节存入 `script.metadata`。

建议的 metadata 键：

- `speaker_map`
- `transcript_path`
- `chapter_candidates`
- `highlight_candidates`
- `rejected_highlights`

### 3. 对高光时刻排序

基于节目逐字稿找出：

- 精炼洞见，
- 令人意外的论断，
- 情绪高点，
- 辩论交锋，
- 实用建议，
- 令人难忘的表述。

每条高光应从以下维度评估：

- 独立可理解性，
- 钩子强度，
- 归属置信度，
- 平台适配度。

### 4. 为长形式打包构建章节

若用户需要完整节目的配套资产，在此识别话题转折。这些将成为章节标记，以及后续视觉转场点。

### 5. 保持 Schema 整洁

用 `sections[]` 存放面向制作的结构化片段，将更丰富的高光清单放在 metadata 中。

### 6. 质量门禁

- 说话人归属可信，
- 高光集合足以支撑所请求的交付物，
- 弱片段应拒绝而非凑数，
- 章节标记能清晰覆盖长对话。

### 制作过程中的事实核查

若在撰写脚本时遇到不确定之处：
- 使用 `web_search` 在写入脚本前核实事实性陈述
- 使用 `web_search` 查找参考图以保证视觉准确性
- 在决策日志中记录核查：`category="visual_accuracy_check"`

脚本中的每条事实性陈述都应能追溯到 `research_brief`。
若陈述不在研究简报中，需补充调研并添加来源。不得编造统计数据、日期或归属信息。

## 常见陷阱

- 将说话人分离错误视为小事，而其实会改变「谁说了这句话」。
- 选取需要过多前文语境才能理解的片段。
- 整批内容过度贴合节目中某一段落。

## 门禁提醒（具有约束力）

本阶段以人工审批为门禁（`human_approval_default: true`）。审查通过后：
以 `status="awaiting_human"` 做 checkpoint，呈现摘要（Backlot 看板会渲染产物），并**结束本轮回复**。勿在同一回复中启动下一阶段。
审批按门禁逐项进行——此前「继续」的许可不覆盖本门禁。
