# 资产总监 - 混合流水线

## 何时使用

本阶段围绕锚点剪辑准备配套工具包：字幕、图表、生成插入镜头、旁白、音乐以及可复用的叠加层系统。

## 前提条件

| 层级 | 资源 | 用途 |
|-------|----------|---------|
| Schema | `schemas/artifacts/asset_manifest.schema.json` | 产物校验 |
| 前置产物 | `state.artifacts["scene_plan"]["scene_plan"]`, `state.artifacts["script"]["script"]`, `state.artifacts["idea"]["brief"]` | 配套需求与变体计划 |
| 工具 | `subtitle_gen`, `tts_selector`, `image_selector`, `video_selector`, `diagram_gen`, `code_snippet`, `music_gen`, `audio_enhance` — 选择器会从注册表自动发现所有可用提供商 | 可选的配套资产生成 |
| Playbook | 当前启用的风格 playbook | 一致性规则 |

## 流程

### 1. 优先构建共享配套资产

从可复用系统入手：

- 字幕处理方案，
- 下三分之一或标签系统，
- 数据卡片系统，
- CTA 容器，
- 图表风格。

### 1b. 样片预览（避免浪费成本）

在批量生成配套资产之前，为每种高成本的生成类型各做一个样片并展示给用户：

1. **TTS 样片**（若需要旁白）：生成一个段落。批量生成前确认音色与语气。
2. **图像/视频样片**（若生成插入镜头）：生成一个代表性画面。批量生成前确认风格与源素材匹配。

若被拒绝，调整参数并重试（最多 3 轮）。未获批准前不要批量生成。

### 2. 只生成你真正需要的配套资产

配套资产应填补脚本与场景计划中已识别的需求，而非为假想可能性过度准备。

### 3. 保持锚点事实清晰

在元数据中明确区分各类资产属于：

- 源自源素材，
- 外部提供，
- 录制所得，
- 生成所得。

### 4. 用元数据构建配套映射

推荐的元数据键：

- `shared_support_assets`
- `scene_asset_index`
- `source_vs_generated_map`
- `variant_assets`

### 5. 质量门

- 配套资产对应真实的叙事需求，
- 可复用工具包齐备，
- 源素材与生成资产界限清晰，
- 所有引用的文件均存在。

### 制作过程中的事实核查

若在资产生成过程中遇到不确定之处：
- 使用 `web_search` 核查主体视觉准确性（例如：该建筑实际长什么样？）
- 使用 `web_search` 在生成插图前查找参考图
- 在决策日志中记录核查：`category="visual_accuracy_check"`

视觉准确性很重要。若脚本提到具体地点、人物或物体，
在生成图像前先核实其真实外观。不要依赖
AI 模型的训练数据——可能错误或过时。

## 常见陷阱

- 在锚点剪辑尚未验证前就过度构建配套资产。
- 搞不清哪些资产是生成的、哪些是提供的。
- 在同一项目中创建不一致的叠加层系统。


## 当你不确定怎么做时

若遇到不熟悉的生成技法、提供商行为或提示模式：

1. **搜索网络** 获取当前最佳实践——模型与 API 更新频繁，智能体的训练数据可能已过时
2. **查阅 `.agents/skills/`** 中已有的 Layer 3 知识（提供商专用提示指南、API 模式）
3. **若仍无法解决**，在 `projects/<project-name>/skills/<name>.md` 编写项目级技能，记录所学内容
4. **在技能中引用来源 URL**，使知识可追溯
5. **写入决策日志**：`category: "capability_extension"`, `subject: "learned technique: <name>"`

以下场景尤其重要：
- **视频生成提示**——各版本模型对特定词汇的响应方式不同
- **图像模型参数**——FLUX、GPT Image、Imagen 等的最优设置各异且持续演进
- **音频提供商特性**——语音克隆、音乐生成与 TTS 各有模型级最佳实践
- **Remotion 组件模式**——框架演进中不断出现新的合成技法

不要依赖过时知识。有疑问时，先搜索。
