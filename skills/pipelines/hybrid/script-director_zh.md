# 脚本导演 - 混合流水线

## 何时使用

本阶段将故事映射到源主导节拍与支持主导节拍上。你要决定哪些段落由源素材承载信息，哪些由支持资产加以澄清。

## 前提条件

| 层级 | 资源 | 用途 |
|-------|----------|---------|
| Schema | `schemas/artifacts/script.schema.json` | 产物校验 |
| 前置产物 | `state.artifacts["idea"]["brief"]` | 锚定媒介与交付物组合 |
| 工具 | `transcriber`, `scene_detect`, `audio_enhance` | 可选的源素材分析 |

## 流程

### 1. 标注源主导与支持主导节拍

对每个章节，说明其由以下哪类方式承载：

- 源对话或镜头画面，
- 旁白，
- 示意图或叠加层，
- 纯文字。

### 2. 源素材口播更强时优先使用

若提供的素材已包含有力台词，使用 `transcriber` 并保留真实感。不要用不必要的旁白替换优质源素材。

### 3. 支持内容仅用于澄清

支持主导节拍应回答：

- 画面中不可见的内容，
- 需要概括的内容，
- 需要强调的内容，
- 针对不同平台需要调整的内容。

### 4. 用元数据组织结构

推荐的元数据键：

- `anchor_sections`
- `support_sections`
- `narration_sections`
- `required_support_assets`

### 5. 质量门禁

- 源主导节拍标注清晰，
- 支持主导节拍有充分理由，
- 脚本不依赖虚假或不可用资产却未说明，
- 结构能产出预期的交付物。

### 制作过程中的事实核查

若在撰写脚本时遇到不确定之处：
- 使用 `web_search` 在写入脚本前核实事实性表述
- 使用 `web_search` 查找参考图以保证视觉准确
- 在决策日志中记录核查：`category="visual_accuracy_check"`

脚本中的每条事实性表述应可追溯到 `research_brief`。
若某表述不在研究材料中，应补充调研并注明来源。不要编造统计数据、日期或归属。

## 常见陷阱

- 将有力的源对话改写成更弱的旁白。
- 在镜头已说明要点处仍添加示意图或卡片。
- 将未获支持资产的需求隐瞒到资产生成阶段。

## 门禁提醒（具有约束力）

本阶段需经人工审批（`human_approval_default: true`）。审查通过后：
以 `status="awaiting_human"` 设置检查点，呈现摘要（Backlot 看板会渲染产物），并**结束本轮回复**。不要在同一条回复中启动下一阶段。
审批按门禁逐项进行——此前「继续」的许可不覆盖本门禁。
