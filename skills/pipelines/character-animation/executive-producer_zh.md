# 执行制片人 - 角色动画流水线

## 何时使用

当交付物依赖可复用的动画角色时使用本流水线：卡通短片、吉祥物讲解、以音乐驱动的角色场景、简单角色之间的对话，或参考驱动的本地动画。

不要将一次性、无表演需求的动态图形交给本流水线，应路由到 `animation`。不要将虚拟人主讲人口型同步类需求交给本流水线，应路由到 `avatar-spokesperson`。

## 契约

本流水线产出本地、确定性的角色动画。不得静默用静图动效替代表演。若现有绑定、资产或运行时无法构建角色动作，必须上报阻塞项。

## 阶段顺序

1. `research` - 理解参考、技法与可行性。
2. `proposal` - 呈现概念、运行时选项、成本、音乐计划与样片计划。
3. `script` - 撰写便于动作设计的节拍与对白/旁白。
4. `character_design` - 定义角色、剪影、情绪与动作。
5. `rig_plan` - 定义部件、枢轴、图层、约束与姿势。
6. `scene_plan` - 将故事节拍映射到角色场景。
7. `assets` - 制作或获取角色部件、背景、道具与音频。
8. `edit` - 编译带时序的动作时间线。
9. `compose` - 经批准的运行时渲染并执行 QA。
10. `publish` - 打包最终输出。

## 治理规则

- 在提案前运行 registry preflight。
- 若 Remotion 与 HyperFrames 均可用，在锁定 `render_runtime` 前须向用户展示两者。
- 在全面资产生成前先制作 10–15 秒样片。
- 角色差异应体现在绑定数据中，而非一次性代码路径。
- 每一处生成或由运行时编写的资产须列出已阅读的 Layer 3 技能。
- 交付前使用 `character_animation_reviewer`，并完成最终 `final_review`。

## 退回触发条件

- `character_design` 缺少必需动作或情绪范围。
- `rig_plan` 缺少可动部件的枢轴。
- `pose_library` 无可读的表演姿势。
- `action_timeline` 含绑定无法渲染的动作。
- 合成阶段使用了提案中未批准的运行时。
