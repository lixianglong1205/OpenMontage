# 提案导演 - 角色动画流水线

## 目标

呈现角色动画概念时，须如实说明本地绑定动作、复用、成本与运行时选择。

## 提案必备要素

每个方案须包含：

- 角色与职责，
- 视觉风格，
- 动作复杂度，
- 绑定复用策略，
- 样片计划，
- 音频架构，
- 音乐计划，
- 渲染运行时选项，
- 成本估算，
- 诚实的局限说明。

## 运行时选择

在推荐运行时间之前，请先阅读 `skills/meta/animation-runtime-selector.md`。

当 Remotion 与 HyperFrames 均可用时：

- Remotion：最适合最终合成需要确定性 React 渲染视频、字幕、音频、场景 JSON 以及最终 MP4 治理的场景。
- HyperFrames：最适合角色场景以 HTML/SVG/GSAP 为主，并受益于 Web 原生创作、lint、validate 与 registry 区块的场景。
- FFmpeg：仅用于后期处理。勿将 FFmpeg 选为角色表演的主运行时。

在推荐其一之前，向用户同时呈现 Remotion 与 HyperFrames。
在决策日志中以 `render_runtime_selection` 记录所考虑的备选方案，包括接受或拒绝 `hyperframes` 的原因。
在锁定 `render_runtime` 之前，等待用户批准。

## 样片优先规则

在全面制作之前，提议一段 10–15 秒的样片，包含：

- 一个主要角色，
- 一次表情变化，
- 一个身体动作，
- 一种镜头/背景处理，
- 若相关，一条音频/音乐提示。

在该样片获批之前，勿批量生成全部资产。

## 成本诚实

本地绑定在渲染时成本低，但创作复杂度高。
须说明以下差异：

- 资产生成成本，
- TTS/音乐成本，
- 本地渲染成本，
- 人工复杂度风险。
