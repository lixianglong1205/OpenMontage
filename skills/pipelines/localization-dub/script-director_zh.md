# 脚本导演 - 本地化配音流水线

## 何时使用

将已批准的本地化简报转化为有转录稿支撑、可审阅的脚本包，覆盖每一种目标语言。本阶段应在生成任何配音音频之前，先确立文本层面的「事实标准」。

## 参考输入

- `docs/localization-dubbing-best-practices.md`
- `skills/creative/storytelling.md`

## 流程

### 1. 建立源转录稿事实标准

从源转录稿出发，修正以下方面的明显错误：

- 人名，
- 术语，
- 说话人归属，
- 数字，
- CTA（Call to Action，行动号召）表述。

### 2. 产出可审阅的目标语言文案

针对每种目标语言，生成可在合成前审阅的文本。记录哪些术语应保持不变。

### 3. 在可行处保留结构

除非翻译明显需要不同的节奏策略，否则尽量使章节时长与顺序与源稿对齐。

### 4. 用元数据控制本地化

建议的元数据键：

- `source_transcript_status`
- `target_language_sections`
- `glossary_terms`
- `protected_terms`
- `pronunciation_notes`
- `review_status_by_language`

### 5. 质量门禁

- 源转录稿足够可靠、可作为依据，
- 每种计划交付物均有目标语言文案，
- 术语表条目得到保留，
- 脚本包可在音频生成前完成审阅。

### 制作过程中的事实核查

若在撰写脚本时遇到不确定之处：
- 使用 `web_search` 在写入脚本前核实事实性陈述
- 使用 `web_search` 查找参考图以保证视觉准确性
- 在决策日志中记录核查：`category="visual_accuracy_check"`

脚本中的每条事实性陈述都应能追溯到 `research_brief`（调研简报）。
若某条陈述不在调研材料中，需补充调研并注明来源。不得编造统计数据、日期或归属信息。

## 常见陷阱

- 从未经审阅的转录稿直接生成音频。
- 产品名称在各语言间发生漂移。
- 将译文视为最终时长，却未考虑长度变化带来的节奏差异。

---

## 门禁提醒（具有约束力）

本阶段以人工批准为门禁（`human_approval_default: true`）。审阅通过后：
使用 `status="awaiting_human"` 创建检查点，呈现摘要（Backlot 看板会渲染对应产物），并**结束本轮回复**。勿在同一轮回复中启动下一阶段。
批准按门禁逐一进行——此前说的「继续」不覆盖本门禁。
