# 场景导演 - 电影感流水线

## 何时使用

你正在决定每个电影感节拍如何呈现以及如何转场。这是将情绪落实为视觉方案的阶段。

## 前提条件

| 层级 | 资源 | 用途 |
|-------|----------|---------|
| Schema | `schemas/artifacts/scene_plan.schema.json` | 产物校验 |
| 前置产物 | `state.artifacts["script"]["script"]`, `state.artifacts["proposal"]["proposal_packet"]` | 节拍映射与事实来源 |
| 工具 | `frame_sampler`, `scene_detect` | 源素材检视与重新构图检查 |
| Playbook | 当前启用的风格 playbook | 色彩与字体一致性 |

## 流程

### 1. 明确英雄帧（Hero Frames）

每支电影感作品都需要若干令人难忘的帧。直接定义：

- 开场画面，
- 揭示画面，
- 收尾画面，
- 任何标题卡英雄时刻。

### 2. 以源素材主导场景为优先

若存在源 footage，让它承担作品主体。生成的插入镜头或文字卡应服务于转场、强调或补全缺失覆盖，而非占据时间线主导。

### 3. 限制转场词汇表

选择少量类型：

- 硬切（hard cut），
- 渐黑（fade to black），
- 慢溶解（slow dissolve），
- 克制的推镜或 punch-in。

转场类型过多会破坏情绪。

### 4. 用元数据承载视觉规则

推荐的 metadata 键：

- `hero_frames`
- `transition_rules`
- `aspect_ratio_rules`
- `title_card_rules`
- `support_insert_rules`

### 5. 场景规划五维检查清单

> 每个场景节拍——尤其是每个英雄帧——必须明确全部五个维度。电影感依赖少量可记忆的帧；英雄帧规格含糊是单一最常见失败模式，会导致模型输出不可预测。某维度可标为 N/A，但必须显式说明（例如「无主体——建立环境的 scenery 镜头」）。禁止静默省略。
>
> 1. **主体（Subject）** — 类型 + 关键视觉属性；若有多主体，如何区分。对英雄帧，身份必须在各镜头间逐字锚定一致。
> 2. **主体运动（Subject Motion）** — 按时间顺序的动作；主体↔物体 / 主体↔主体 交互。
> 3. **场景（Scene）** — 叠加层（单独列出！）+ 视点 + 环境 + 时段 + 场景动态。
> 4. **空间构图（Spatial Framing）** — 景别 + 画内位置 + 景深（前景/中景/背景）+ 相对机位高度；以及这些在节拍内如何**变化**。
> 5. **摄影机（Camera）** — 播放速度 → 镜头畸变 → 高度 → 角度 → 对焦/景深 → 稳定性 → 运动。
>
> 原语词汇见 `skills/creative/video-gen-prompting.md`。

> **叠加层说明。** 叠加层（标题、字幕、HUD、水印、画框图形、下三分之一、姓名条、片尾卡）**不属于**场景的前景/中景/背景景深轴。在场景 metadata 中单独列出（`overlays: [...]`），写明内容与位置。切勿把叠加层描述为「在前景中」——那会混淆下游工具以及任何重新分析输出的 video-understanding 模型。

### 6. 质量门

- 每个节拍都有场景处理方案，
- 英雄帧可识别且在五个维度上完整指定，
- 辅助插入有充分理由，
- 叠加层记录在 `overlays:` 下，从不写入景深/构图描述，
- 整片视觉语言保持一致。

## 常见陷阱

- 把标题卡当填充物。
- 把生成插入当作主叙事却不声明。
- 为每个节拍规划花哨转场。
