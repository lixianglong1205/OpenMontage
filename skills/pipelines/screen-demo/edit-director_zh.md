# 剪辑导演 - 屏幕演示流水线

## 何时使用

本阶段将计划转化为具体、符合 schema 的剪辑决策：裁剪、变速、叠加层、字幕与转场。剪辑应足够简单以便现有工具链执行，又足够明确以便合成阶段可预测。

## 前提条件

| 层级 | 资源 | 用途 |
|-------|----------|---------|
| Schema | `schemas/artifacts/edit_decisions.schema.json` | 产物校验 |
| 前置产物 | `state.artifacts["assets"]["asset_manifest"]`、`state.artifacts["scene_plan"]["scene_plan"]`、`state.artifacts["script"]["script"]` | 素材、视觉计划、时间线 |
| Playbook | 当前启用的风格 playbook | 叠加层与节奏规则 |

## 流程

### 1. 从最小且清晰的剪辑开始

屏幕演示一旦被过度剪辑就会变差。按以下顺序构建时间线：

1. 裁剪或剪掉无效时段，
2. 应用变速，
3. 放置叠加层，
4. 设定字幕行为，
5. 定义音频行为，
6. 在 `edit_decisions.metadata` 中记录详细的裁剪/变速说明。

### 2. 保持 Schema 整洁

用 `cuts[]` 表示实际源片段与变速。仅对 schema 已建模的内容使用 `overlays[]`、`subtitles`、`music` 和 `transitions`。将屏幕演示特有的细节放在 metadata 中：

- `crop_keyframes`
- `speed_plan`
- `subtitle_position_overrides`
- `audio_notes`
- `variant_notes`

### 3. 剪辑规则

- 观众应在最初几秒内看到有用的动作或结果，
- 结果时刻保持正常速度，
- 打字、安装与等待应加速或删除，
- 不得在词中间起剪，也不得在 payoff 落地前结束，
- 不要通过剪辑引入比场景计划更多的动效。

### 4. 叠加层规则

- 钩子或步骤标签可立即出现，
- 标注应略早于动作出现，
- 模糊遮罩必须视为关键项，而非可选，
- 字幕与标注不得争夺同一空间。

### 5. 音频规则

- 保持主语音清晰且居中，
- 对无意义的加速噪声静音或大幅压低，
- 仅当背景音乐有价值且能在 ducking 下自然存在时才使用，
- 若已生成旁白，确保其适配收紧后的时间线。

### 6. 质量门

**时间线完整性：**
- [ ] 裁剪覆盖完整预期时间线
- [ ] 无意外黑场间隙
- [ ] 变速 ramp 不重叠
- [ ] 有效时长与 brief 紧密一致

**叠加层完整性：**
- [ ] 每个计划中的标注或遮罩均有对应项
- [ ] 无叠加层碰撞
- [ ] 锚定在 UI 上的叠加层文档足够清晰，便于合成阶段定位

**音频完整性：**
- [ ] 主音频或旁白覆盖整条时间线
- [ ] 加速片段有明确的音频处理
- [ ] 若有音乐，不会与讲解争抢

**字幕完整性：**
- [ ] 所有旁白段落均有字幕
- [ ] 位置 override 保护重要 UI 内容
- [ ] 计划变速后字幕时间仍正确

## 常见陷阱

- 过度堆砌工作流不需要的电影感转场。
- 让加速后的音频变成刺耳的点击与打字声墙。
- 忘记裁剪与变速计划写在 metadata 中，而非任意 schema 字段。
