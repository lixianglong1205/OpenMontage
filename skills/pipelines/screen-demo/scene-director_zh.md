# 场景导演 - Screen Demo 流水线

## 适用场景

你正在规划观众注意力如何在已有屏幕录制中移动。源视频已经存在；你的任务是决定何时保持全景、何时裁切放大，以及何时添加最简引导。

## 前提条件

| 层级 | 资源 | 用途 |
|-------|----------|---------|
| Schema | `schemas/artifacts/scene_plan.schema.json` | 产物校验 |
| 前置产物 | `state.artifacts["script"]["script"]`, `state.artifacts["idea"]["brief"]` | 脚本时间轴与源素材说明 |
| 工具 | `frame_sampler`, `scene_detect` | 提取参考帧与转场 |
| Playbook | 当前启用的风格 playbook | 叠加层样式与节奏规则 |

## 流程

### 1. 规划注意力，而非持续运动

现代屏幕演示工具普遍采用点击驱动的缩放，以减少随意的镜头运动。在此遵循同一原则：

- 仅在观众确实需要帮助阅读或定位某处时放大，
- 在理解阶段保持画面稳定，
- 当关键事件没有点击锚点时手动放大，
- 在主要步骤之间重置为更宽的全景上下文。

对每个关键动作，用 `frame_sampler` 获取精确的参考帧，并将详细的裁切说明写入 `scene_plan.metadata`。

### 2. 选择场景形态

使用与 schema 匹配的简单场景类型：

- `screen_recording`：实时 UI 录制片段
- `text_card`：步骤标签、标题卡或回顾幻灯片
- `diagram`：仅当 UI 本身无法说明概念时使用
- `transition`：仅在主要工作流阶段之间少量使用

### 3. 在 Metadata 中规划裁切策略

schema 没有一等公民的 zoom 对象，因此场景描述保持简洁，将详细裁切计划放在 `scene_plan.metadata.crop_regions`。

推荐的 `crop_regions` 字段：

- `section_id`
- `start_seconds`
- `end_seconds`
- `region`
- `zoom_level`
- `trigger`（`click_cluster`, `typing`, `result`, `manual_focus`）
- `transition_duration`
- `rationale`

实用启发式：

| UI 元素 | 缩放级别 | 区域尺寸 | 说明 |
|------------|-----------|---------------|-------|
| 终端 / 代码 | 1.5-2.2x | 保留足够周边上下文，便于观众定位 |
| 小按钮 / 图标 | 2.0-3.0x | 留出边距，让观众知道它在界面中的位置 |
| 模态框 / 对话框 | 1.4-2.0x | 框住完整模态，不要裁切局部 |
| 整页结果 | 1.0-1.3x | 再次放大前多展示一些上下文 |

### 4. 克制地规划标注

在 `required_assets` 与 `metadata.callout_plan` 中记录叠加层需求。

仅使用能澄清动作的模式：

- `highlight_box`
- `arrow`
- `step_label`
- `keystroke_badge`
- `blur_mask`

规则：

- 同时不超过两个注意力提示，
- 在动作发生前稍早显示提示，
- 动作结束后快速移除，
- 优先高亮或缩放；除非可读性确实需要，否则不要两者叠加。

### 5. 规划速度处理

将重复片段标记为以下之一：

- `speed_up`
- `cut`
- `realtime`

对加速片段可用的视觉处理：

- 进度标签，
- 小字状态文本，
- 对删去的等待段做简单 dissolve。

不要为安装、构建或长段输入发明花哨的转场效果。

### 6. 按片段选择宽高比

若整项面向多种输出，在 metadata 中注明哪些场景裁切适用于：

- `16:9`
- `1:1`
- `9:16`

若某步骤无法适配竖屏，请明确说明。正确答案有时是仅交付横屏，或单独制作简化的竖屏版本。

### 7. 质量门禁

**缩放一致性：**
- [ ] 运动是有意图的，而非持续不断
- [ ] 每次放大都是为了可读性或定位
- [ ] 每个主要段落都有更宽的重建立镜头
- [ ] 裁切不会切掉相关文字或控件

**标注一致性：**
- [ ] 每个关键动作都有裁切或标注之一
- [ ] 标注不遮挡 UI
- [ ] 字幕区与标注区不冲突
- [ ] 敏感数据已有计划的遮罩

**节奏一致性：**
- [ ] 结果时刻保持正常速度
- [ ] 等待与重复输入被压缩或删除
- [ ] 成片时长仍与 brief 一致

## 常见陷阱

- 长时间保持放大，导致观众失去界面整体地图。
- 为宽 UI 规划竖屏裁切却不承认会失败。
- 到处加高亮层，而不是选择单一最清晰的提示。
- 忽略看似次要帧中暴露的敏感数据。
