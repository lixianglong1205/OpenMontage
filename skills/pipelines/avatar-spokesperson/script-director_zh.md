# 脚本导演 - Avatar Spokesperson Pipeline

## 何时使用

将已批准的简报转化为适合分镜的口播文案，供虚拟形象主持人呈现。质量标杆不是文采，而是口播清晰度、可信的节奏，以及每个场景一个清晰要点。

## 参考输入

- `docs/avatar-spokesperson-best-practices.md`
- `skills/creative/storytelling.md`

## 流程

### 1. 为口播而写，而非为幻灯片而写

优先：

- 短句，
- 直接动词，
- 每个节拍一个想法，
- 明确的过渡，
- 对话式强调。

若文案朗读起来像宣传册，请重写。

### 2. 拆分为适合分镜的段落

虚拟形象场景在每一节都紧凑时更易管理。实用的起点包括：

- 钩子（hook），
- 价值陈述，
- 证明或功能节拍，
- 行动号召（CTA）。

### 3. 保持屏幕文字精简

主持人已在承担注意力。屏幕文字仅用于：

- 产品名称，
- 简短证明要点，
- CTA 文案，
- 必须出现的法律或合规文字。

### 4. 用元数据记录交付说明

推荐的元数据键：

- `scene_copy_map`
- `cta_language`
- `pronunciation_notes`
- `supplied_script_source`
- `legal_text_requirements`

### 5. 质量门

- 文案听起来像口播，
- 场景时长现实可行，
- CTA 位置清晰，
- 文字叠加克制。

### 制作过程中的事实核查

若在撰写脚本时遇到不确定之处：
- 使用 `web_search` 在将事实性陈述写入脚本前进行核实
- 使用 `web_search` 查找参考图片以保证视觉准确性
- 在决策日志中记录核查：`category="visual_accuracy_check"`

脚本中的每条事实性陈述都应能追溯到 `research_brief`。
若你做出简报中未包含的陈述，请补充调研并
添加来源。不要编造统计数据、日期或归因。

## 常见陷阱

- 因脚本在纸面上读得顺，而在一个场景里塞入过多内容。
- 在口播与大号文字叠加中重复同一句。
- 撰写虚拟形象路径无法呈现的幽默或即兴节拍。
