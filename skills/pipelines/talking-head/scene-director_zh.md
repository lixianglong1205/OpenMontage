# Scene Director — Talking Head 流水线

## 何时使用

你已有脚本（来自转写）和原始素材。你的任务是**观看素材、理解内容，并提出创意增强方案**——然后构建场景计划，将原始 talking-head 素材转化为引人入胜、视觉丰富的视频。

你不只是处理器。你是创意总监。你要弄清演讲者在说什么，并提议能让内容更易理解、更吸引人的视觉增强。

## 前提条件

| 层级 | 资源 | 用途 |
|-------|----------|---------|
| Schema | `schemas/artifacts/scene_plan.schema.json` | 产物校验 |
| 前置产物 | Script、Brief | 分段时长与上下文 |
| 工具 | `frame_sampler`（可选） | 提取代表性帧 |
| 工具 | `face_tracker`（可选） | 分析说话人面部位置以便重构图 |
| 工具 | `silence_cutter`（可选） | 检测静音以规划跳切 |

## 流程

### 步骤 0：素材分析

在观看内容之前，先分析原始素材以了解物理布置。

1. **采样 5 帧**：使用 ffmpeg 从素材中均匀间隔采样：
   ```
   ffmpeg -i <footage> -vf "select='not(mod(n\,TOTAL_FRAMES/5))'" -vsync vfr -frames:v 5 frame_%02d.png
   ```

2. **对每帧运行 visual_qa 或直方图分析**，以检测：
   - **背景类型：** 绿幕 / 蓝幕 / 自然背景。绿幕/蓝幕在直方图中会呈现主导的单色窄带峰值。可用 `visual_qa` 配合提示「这是绿幕还是蓝幕背景？」进行确认。
   - **说话人位置：** 画面居中、偏左或偏右。估算大致边界框（例如「说话人占画面中央 40%，从 x=30% 到 x=70%」）。
   - **光照质量：** 均匀棚拍光、硬阴影、逆光、混合色温等。记录可能影响色度键的任何问题。

3. **检测到绿幕？**
   - 若是，注明 compose 阶段需要 `green_screen_processor` 工具。
   - 记录检测到的幕色（绿或蓝）及均匀度估计。
   - compose-director 将据此做色度键抠像并合成到动画背景上。

4. **测量说话人安全区：**
   - 根据说话人边界框，确定图形可放置且**不会遮挡说话人**的区域。
   - 居中说话人：左侧面板与右侧面板适合叠加层。
   - 偏左说话人：右侧面板为主要安全区。
   - 偏右说话人：左侧面板为主要安全区。
   - 无论说话人位置，画面上三分之一与下三分之一通常都较安全。

将所有发现记入场景计划元数据，供下游阶段使用。

### 步骤 1：观看与聆听 — 理解内容

**这是最重要的一步。不可跳过。**

仔细阅读完整转写。理解：
- 演讲者的**主题**是什么？
- 他们解释了哪些**关键概念**？
- 在何处提到**数字、统计或数据**？
- 在何处**对比事物**（A 对 B、前后对比、新旧对比）？
- 在何处**列举条目**（3 个技巧、5 个步骤等）？
- 在何处引入**术语**或行话？
- **分段转折**在哪里（话题切换）？
- **情绪弧线**如何（兴奋、严肃、幽默）？

若可用 `frame_sampler`，提取 5–8 张代表性帧，观察说话人的布置、背景、光照与手势。

### 步骤 2：提议创意叠加层

基于内容分析，在关键时刻提议与说话人同框或相邻的**屏幕图形**。这些是 Remotion 组件，叠加在 talking-head 素材之上或旁边。

**可用叠加类型：**

| 叠加类型 | Remotion 组件 | 适用场景 |
|-------------|-------------------|----------|
| **术语定义** | `text_card` | 演讲者引入技术术语时 — 显示术语 + 简短定义 |
| **统计/数字** | `stat_card` | 提到数字或百分比时 — 在屏幕上动画呈现 |
| **对比** | `comparison` | 对比两件事（A 对 B）— 并排展示 |
| **数据图表** | `bar_chart` / `pie_chart` / `line_chart` | 引用数据或排名时 |
| **KPI 仪表盘** | `kpi_grid` | 同时提到多个数字时 |
| **进度指示** | `progress_bar` | 描述流程或百分比时 |
| **章节标题** | `hero_title` | 主要话题切换时 — 显示新章节标题 |
| **强调/引用** | `callout` | 值得强调的关键观点 |
| **下三分之一条** | `text_card` | 开场时的说话人标识 |

**Remotion 组件约束：**

| 组件 | 最小宽度 | 720px 竖屏？ | 值类型 |
|-----------|-----------|-----------------|------------|
| comparison | 900px | 否 -> 改用 2 个 stat_card | string |
| kpi_grid | 720px | 是 | 仅 numeric（不可用「15+」） |
| bar_chart | 500px | 是 | numeric |
| stat_card | 300px | 是 | 允许 string |
| callout | 400px | 是 | string |
| hero_title | 400px | 是 | string |
| line_chart | 500px | 是 | numeric |
| progress_bar | 600px | 是 | numeric |
| stat_reveal | 300px | 是 | 允许 string |

当组件最小宽度超过可用空间（例如 720px 竖屏放不下 900px 的 `comparison`）时，改用推荐替代方案。对 `comparison`，可改为依次展示两个 `stat_card`。

对 `kpi_grid`，值**必须**为 numeric（如 `4.8`、`73`、`2400`）。像 `"15+"` 或 `"$4.8B"` 这类字符串会导致渲染错误。字符串格式的数字请用 `stat_card`。

**叠加规划规则：**
- **勿过度叠加。** 成片每分钟 3–6 个叠加为宜，过多会分散注意力。
- **叠加与语音同步。** 每个叠加应在演讲者说到相关内容时出现，而非提前或滞后。
- **叠加要短。** 每个 3–5 秒。它们辅助说话人，而非与之竞争。
- **类型多样化。** 不要连续 5 个 text_card — 穿插图表、对比、callout。
- **在自然停顿处使用叠加。** 演讲者为强调而停顿时，是较好的叠加时机。
- **匹配调性。** 专业演讲 = 简洁 stat_card 与图表； casual 演讲 = callout 与醒目术语。

### 步骤 3：向用户展示计划

**强制：继续之前必须先展示增强计划。**

清晰格式化提案：

```
## [视频标题/主题] 增强计划

**内容摘要：** [1–2 句概括演讲内容]

**提议的叠加层：**

| 时间 | 类型 | 内容 | 原因 |
|------|------|---------|-----|
| 0:05 | lower_third | "Speaker Name — Title" | 说话人介绍 |
| 0:22 | text_card | "Agentic AI: software that acts autonomously" | 关键术语定义 |
| 0:45 | comparison | Traditional Software vs Agentic Software | 演讲者在对比两者 |
| 1:10 | stat_card | "73% of developers..." | 提到的统计数据 |
| 1:35 | bar_chart | [Framework popularity data] | 演讲者引用排名 |
| 2:00 | callout | "The key insight is..." | 演讲者主要结论 |

**增强链：**
- 静音移除：检测到约 X 秒空白
- 倍速：1.25x（用户要求）
- 面部 + 眼部增强
- 动画字幕（画面底部）
- 背景音乐：[建议]

**预估成片时长：** 约 Xs（原始 Xs）
```

**重要：输出叠加计划时，还须生成实际的 Remotion JSON props 文件（`greenscreen-bg.json`）——不要只用散文描述场景。** JSON props 应是 Remotion TalkingHead 合成的完整、有效输入，包含所有叠加定义、时间、颜色与内容。保存到 `<project>/public/demo-props/` 或项目的 props 目录。

等待用户批准后再继续。用户可能：
- 原样批准
- 增删叠加
- 修改叠加内容
- 调整增强计划

### 步骤 4：分析素材（若工具可用）

**人脸跟踪** — 若可用 `face_tracker`，对原始素材运行：
```
face_tracker.execute({
    "input_path": "<raw_footage>",
    "sample_fps": 5
})
```
输出逐帧人脸边界框。用该数据：
- 判断是否需要重构图（例如竖屏裁剪时说话人偏轴）
- 识别说话人移动明显的片段（需动态裁剪）
- 记录 compose 阶段 auto_reframe 的人脸位置
- **确定叠加安全区** — 图形放置位置且不遮挡面部

**静音检测** — 若可用 `silence_cutter`，以 `mark` 模式运行：
```
silence_cutter.execute({
    "input_path": "<raw_footage>",
    "mode": "mark",
    "silence_threshold_db": -35,
    "min_silence_duration": 0.5
})
```
输出静音/语音片段时间戳。用于：
- 规划哪些片段应跳切或加速
- 识别空白、误起与长停顿
- 估算剪辑后成片时长

### 步骤 5：规划基础场景

对 talking-head，基础结构简单：每个脚本分段一个场景，类型均为 `talking_head`。原始素材即场景本身。

### 步骤 6：构建叠加场景

对步骤 3 中每个已批准的叠加，创建叠加场景条目：
```json
{
  "id": "overlay_1",
  "type": "overlay",
  "overlay_type": "text_card",
  "start_seconds": 22.0,
  "duration_seconds": 4.0,
  "content": {
    "text": "Agentic AI",
    "subtext": "Software that acts autonomously toward goals",
    "backgroundColor": "<theme_background>",
    "accentColor": "<theme_accent>"
  },
  "position": "lower_third"
}
```

**叠加位置选项：**
- `lower_third` — 画面下 30%（最安全，不挡脸）
- `upper_third` — 画面上 30%（适合标题）
- `side_panel` — 左或右 40%（图表/对比，说话人移到另一侧）
- `full_overlay` — 短暂全屏图形（最多 1–2 秒，用于强调）

### 步骤 7：规划重构图与剪辑

若目标平台需要不同宽高比（例如 Instagram Reels = 9:16）：
- 注明 compose 阶段应应用 `auto_reframe`
- 在场景计划中记录目标宽高比
- 若人脸跟踪显示说话人移动明显，注明需要动态裁剪

若静音检测发现应剪掉的片段：
- 在场景计划中记录推荐剪切模式（`remove` 或 `speed_up`）
- 注明 padding 偏好（默认 0.08s，避免截断词语）

### 步骤 8：构建场景计划

组装完整场景计划，包含：
- 基础场景（每个脚本分段一个，类型 `talking_head`）
- 叠加场景（来自步骤 6，类型 `overlay`）
- 增强链决策（静音剪切模式、倍速系数、重构图目标）
- 音乐建议
- 预估成片时长

### 步骤 9：自评

| 标准 | 问题 |
|-----------|----------|
| **内容理解** | 是否真正理解演讲者在讲什么？ |
| **叠加相关性** | 每个叠加是否直接对应该时刻所讲内容？ |
| **叠加密度** | 是否在每分钟 3–6 个范围内？不过疏也不过密？ |
| **叠加多样性** | 是否使用不同类型，而非只有 text_card？ |
| **时间对齐** | 叠加是否对齐演讲者词句，而非任意时刻？ |
| **覆盖度** | 每个脚本分段是否都有场景？ |
| **可行性** | 所有叠加是否可用现有 Remotion 组件渲染？ |
| **用户批准** | 用户是否已批准增强计划？ |

### 步骤 10：提交

对照 schema 校验 scene_plan，并通过 checkpoint 持久化。
