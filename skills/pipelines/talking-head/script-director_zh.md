# 脚本导演 — 口播（Talking Head）流水线

## 何时使用

你已有简报和原始口播素材。你的任务是转录素材，并将其整理为带时间戳分段的脚本制品（script artifact）。

与讲解类流水线（从零撰写脚本）不同，你是在提取并结构化已有口播内容。

## 前提条件

| 层级 | 资源 | 用途 |
|------|------|------|
| Schema | `schemas/artifacts/script.schema.json` | 制品校验 |
| 前置制品 | `state.artifacts["idea"]["brief"]` | 内容上下文 |
| 工具 | `transcriber`（WhisperX） | 带时间戳的语音转文字 |

## 流程

### 步骤 1：转录

使用 transcriber 工具获取词级时间戳：
- 模型：`large-v3` 质量最佳，`base` 速度更快
- 启用词级对齐以获得精确时间
- 记录语言检测结果

### 步骤 2：分段

将转录文本按逻辑划分为多个段落：
- 根据内容识别话题切换
- 尊重自然停顿（静音 > 1.5 秒可作为分段点）
- 每段包含：id、text、start_seconds、end_seconds

### 步骤 3：增强段落元数据

为每段补充：
- 增强提示（enhancement cues：可叠加 overlay、b-roll 或文字卡的位置）
- 讲者备注（从音频中识别的重音、语速变化）

### 步骤 4：构建脚本制品

组装结构化脚本，包含：
- 总时长（来自转录）
- 所有带时间戳的段落
- 每段的增强提示

### 步骤 5：自评

| 标准 | 问题 |
|------|------|
| **转录准确度** | 文字是否正确？（抽查若干段落） |
| **时间戳准确度** | 段落边界是否与实际口播对齐？ |
| **覆盖度** | 脚本是否覆盖素材全长？ |

### 步骤 6：提交

对照 schema 校验脚本，并通过 checkpoint 持久化。

### 制作过程中的事实核查

若在撰写脚本时遇到不确定信息：
- 使用 `web_search` 在写入脚本前核实事实性陈述
- 使用 `web_search` 查找参考图以保证视觉准确性
- 在决策日志中记录：`category="visual_accuracy_check"`

脚本中的每条事实性陈述应可追溯到 `research_brief`。
若陈述不在调研简报中，需补充调研并添加来源。不得编造统计数据、日期或出处。
