# 屏幕录制流程

> 参考来源：OBS Studio 文档、Loom 制作指南、Fireship 制作方法论、Kevin Powell CSS 教程技巧、Theo Browne 开发者内容指南

## 快速参考卡

```
RESOLUTION:       1920x1080 at 2x display (record at 3840x2160, deliver at 1080p)
FRAME RATE:       60fps for UI/scrolling, 30fps for static code
CURSOR:           Enlarged (1.5-2x), highlighted with ring or glow
ZOOM:             1.5-2x for code focus, 0.8s ease-in-out transition
SPEED RAMP:       1.5x for navigation, 2x for repetitive actions, 1.0x for key moments
DEAD AIR:         Remove pauses > 1.5 seconds
FONT SIZE (IDE):  18-22px minimum for readability at 1080p delivery
```

## 录制设置

### 分辨率策略

| 方案 | 录制分辨率 | 交付分辨率 | 原因 |
|----------|----------|-----------|-----|
| **推荐** | 3840x2160 (4K) | 1920x1080 | 可对代码做 2 倍放大而不损失画质 |
| 经济方案 | 1920x1080 | 1920x1080 | 直接采集，放大余量有限 |
| 竖屏 | 2160x3840 | 1080x1920 | 竖屏短内容录屏 |

### 帧率

| 内容类型 | FPS | 原因 |
|-------------|-----|-----|
| 写代码（多为静态画面） | 30 | 文件更小，观感差异不明显 |
| UI 操作、滚动 | 60 | 滚动与光标移动更顺滑 |
| 带动画的演示 | 60 | 运动更清晰 |
| 终端输出 | 30 | 文本更新无需 60fps |

### IDE/编辑器设置

- **字号：** 至少 18–22px（交付 1080p 时必须可读）
- **主题：** 优先深色主题（更护眼，在视频中观感更好）
- **行号：** 开启（便于观众跟读）
- **Minimap：** 关闭（占空间、易分心）
- **侧边栏：** 收起，除非本段就是要展示目录结构
- **状态栏：** 可考虑隐藏（挤占画面底部）
- **缩放级别：** 150–175% 以提升可读性

## 光标管理

### 可见性

| 设置 | 数值 |
|---------|-------|
| 光标大小 | 系统默认的 1.5–2 倍 |
| 高亮 | 黄色或白色光圈/光晕（半径 50px） |
| 点击反馈 | 点击时短暂闪光或涟漪 |
| 平滑 | 轻度平滑，减少抖动 |

### 光标行为

- **移动要有目的** — 避免无意义乱晃
- **点击前在目标上停顿** 0.5 秒
- **避免绕圈** — 不要用光标围着讲解对象画圈
- **不需要时隐藏光标**（纯讲代码时）

## 缩放与平移

### 缩放级别

| 场景 | 缩放 | 过渡时长 |
|---------|------|----------------------|
| 全屏概览 | 1.0x (100%) | — |
| 聚焦代码 | 1.5–2.0x | 0.8s ease-in-out |
| 聚焦终端 | 1.5x | 0.6s ease-in-out |
| 高亮 UI 元素 | 2.0–2.5x | 0.8s ease-in-out |
| 回到概览 | 1.0x | 0.6s ease-in-out |

### 平移规则

- 平移应跟随当前操作区域 — 别让观众自己找
- 平滑平移（ease-in-out），不要瞬间跳切
- 每次平移后至少 **停留 3 秒** 再动
- 放大前口头交代：「我们来看这个函数……」

## 后期处理

### 变速（Speed Ramping）

| 动作 | 速度 | 说明 |
|--------|-------|-------|
| 输入样板代码 | 2–3x | 观众不必看你逐字打 import |
| 切换文件/标签 | 1.5–2x | 打开文件、切 tab |
| 安装依赖 / 构建 | 2–4x 或直接剪掉 | 只展示开始与结束，跳过等待 |
| 关键代码编写 | 1.0x | 重要片段保持真实速度 |
| 调试 / 思考 | 1.0x 并剪去空档 | 去掉死寂停顿，保留推理过程 |

### 去除空档（Dead Air）

- 除非刻意留白，**去掉所有超过 1.5 秒的停顿**
- 尽量去掉「嗯、啊」、打错字与退格（在可行范围内）
- 跳切在录屏类内容中可接受且常见
- 每次跳切处可加轻微 **缩放变化**（1.0x → 1.02x）以弱化剪辑痕迹

### 音频增强

- 使用 `audio_enhance` 的 `clean_speech` 预设
- 80Hz 高通滤波（HPF），削弱键盘/桌面低频 rumble
- 3:1 压缩，使口播音量更均匀
- 录屏内容目标 **-16 LUFS**（略低于 -14，长时间观看更舒适）

## 在 OpenMontage 中的应用

在 talking-head 流程中处理屏幕录制时：

1. **尽量以 4K 录制** — 便于后期高质量放大
2. **开录前将 IDE 字号设为 20px 及以上**
3. **使用 `scene_detect`**，threshold 30、min_scene_length 2.0s，切分自然段落
4. **在 compose 阶段做缩放/平移** — 代码区 1.5–2x，过渡 0.8s
5. **导航类片段变速至 1.5–2x**，关键瞬间保持 1.0x
6. **用 `video_trimmer` 去掉超过 1.5s 的空档**
7. **若录制时未带光标高亮，可在后期补上**
8. **目标 -16 LUFS**（略低于 YouTube 常见标准，观看更舒适）
9. **建议加字幕** — 用 `subtitle_gen` 提升可访问性
10. **深色主题在视频中效果最好** — 开录前向用户推荐
