# 提示词扩展（Prompt Expansion）

每次编排（composition）都要执行。扩展的目的不是把短提示词变长——而是将用户意图锚定到设计规范（`frame.md` 或 `design.md`）与 `house-style.md`，并产出一份一致的中间产物，供所有下游智能体以相同方式阅读。

在设计方向确立之后（步骤 1）运行。扩展会消费设计规范（若存在则为 `frame.md` 或 `design.md`），并产出引用其精确取值的输出。

## 前提条件

生成前请先阅读：

- 设计规范 — `frame.md` → `design.md` → `DESIGN.md`（读取第一个存在的文件）— 提取品牌色、字体、氛围与约束。扩展必须引用这些精确取值（十六进制色码、字体名称）；不得自行发明新值。
- `references/beat-direction.md` — 逐 beat 的规划格式（概念、氛围、编排动词、转场、景深层次、节奏）。扩展按此格式输出每个场景。
- `references/video-composition.md` — 视频媒介在密度、尺度与色彩呈现上的规则。扩展会自动应用这些规则。
- `house-style.md` — 其中关于背景层（2–5 个装饰元素）、色彩、动效、字体的规则适用于每个场景。扩展写出的输出须符合这些规则。

若尚无设计规范（`frame.md` 或 `design.md`），请先执行步骤 1（设计系统）。没有设计上下文就做扩展，只会得到通用场景拆解，后续智能体会忽略它们。

## 为何始终要跑

**扩展绝不是透传。** 无论用户提示词多详细，它都只是 _种子_。扩展的任务是将其充实为可直接供场景子智能体构建的、逐场景的完整制作规格。

即便一份详尽的 7 场景简报，仍缺少只有扩展能补上的内容：

- **每个场景的氛围层**（house-style 要求 2–5 个：径向光晕、幽灵字、发丝线、颗粒、主题装饰等）— 用户提示词几乎不会列全；由扩展补上。
- **每个装饰元素的次级动效** — 呼吸、漂移、脉冲、轨道。没有环境动效的装饰会显得死板。
- **让场景显得真实的微细节** — 套准标记、刻度指示、等宽坐标标签、字体点缀、背景代码片段、网格图案。用户往往想不到要提这些。
- **对象级转场编排** — 不是「交叉叠化」，而是「X 向外展开并变成 Y」。具体的时长、ease、变形源/目标。
- **场景内的节奏 beat** — 张力在哪里累积、哪里留白让观众喘息、强调词在哪里落下。
- **来自设计规范的精确十六进制、字体参数、ease 选择** — 不留模糊空间让场景子智能体去猜。

面对详细提示词，扩展的工作不是摘要或透传——而是 **在用户所写之上加厚**：用户内容保留；氛围、环境动效与微细节叠加上去。这才区分「符合简报的场景」与「有生命感的场景」。

单遍编排与多场景流水线编排之间的质量差距，主要来自这一步。扩展前置丰富度，让每个场景子智能体从充实简报而非简略简报出发构建。

**不要跳过。不要透传。** 仅单场景编排与琐碎编辑为例外。

## 要生成什么

扩展为包含以下章节的完整制作提示词：

1. **标题 + 风格块** — 引用设计规范中的精确十六进制、字体名称与氛围。不要发明调色板 — 引用设计所提供的内容。

2. **节奏声明** — 在展开任何场景之前先命名场景节奏。示例：`hook-PUNCH-breathe-CTA` 或 `slow-build-BUILD-PEAK-breathe-CTA`。按视频类型使用 `references/beat-direction.md` 中的节奏模板。

3. **全局规则** — 视差层、微动效要求、转场风格、主转场 + 强调转场。动效能量与氛围匹配（平静 → 慢 ease，高能量 → 利落 ease）。

4. **逐场景 beat** — 每个场景使用 beat-direction 格式：
   - **Concept（概念）** — 用 2–3 句话概括大想法。怎样的视觉 _世界_？什么隐喻？观众应 _感受_ 什么？
   - **Mood direction（氛围方向）** — 文化/设计参考，而非十六进制。（「包豪斯色彩研究」「电影片头序列」「编辑式静气」）
   - **Depth layers（景深层）** — BG（2–5 个带环境动效的装饰）、MG（内容）、FG（点缀、结构元素、微细节）。按 video-composition.md，每场景共 8–10 个元素。
   - **Animation choreography（动画编排）** — 每个元素的具体动词。高能量：SLAMS、CRASHES。中：CASCADE、SLIDES。低：floats、types on、counts up。每个元素都要有动词。若叫不出动词，说明元素尚未设计完成。
   - **Transition out（出场转场）** — shader 或 CSS，含具体类型与参数。不是「crossfade」，而是「blur crossfade, 0.4s, power2.inOut.」

5. **Recurring motifs（复现母题）** — 跨场景、来自品牌调色板的视觉线索。

6. **Negative prompt（负向提示）** — 要避免的内容；若设计规范中有约束则据此填写。

## 输出

将扩展后的提示词写入项目目录下的 `.hyperframes/expanded-prompt.md`。不要 dump 到聊天里 — 会有数百行。

告诉用户：

> "我已将你的提示词扩展为完整制作拆解。请在此审阅：`.hyperframes/expanded-prompt.md`
>
> 共 [N] 个场景、[duration] 秒，含具体视觉元素、转场与节奏。可随意编辑，准备好继续时告诉我。"

仅在用户批准或表示继续之后，再进入构建阶段。
