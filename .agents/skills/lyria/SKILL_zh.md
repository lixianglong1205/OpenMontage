# Google Lyria 3

将 Lyria 3 作为单轮音乐生成器使用。须与 Lyria RealTime 区分：后者是用于持续可控器乐演奏的实验性 WebSocket 模型。

在选型、设计人声或自定义歌词、使用图像输入、调试响应或查阅当前限制与定价时，请阅读 [references/api-and-prompting.md](references/api-and-prompting.md)。

## 必需工作流

1. 确认预期用途：铺底、循环、器乐提示或完整歌曲。
2. 确认人声、语言、目标时长、音乐结构与交付格式。
3. 说明提供商、确切模型、单次请求预估费用，以及本次调用是探索性还是最终成片。
4. 按下方契约撰写一条结构化提示词。
5. 执行一次经批准的生成调用。重试应视为另一次可能计费的随机生成。
6. 原样保留返回的提供商源文件。
7. 在记录时长、格式或批准元数据之前，对实际文件做探测并试听。
8. 当剪辑需要精确时长时，另行导出制作母版。

## 模型选型

| 需求 | 模型 | 契约 |
|---|---|---|
| 提示词迭代、预览、循环、精确 30 秒源素材 | `lyria-3-clip-preview` | 始终生成 30 秒 MP3；当前 $0.04/次 |
| 完整歌曲、人声、更长结构、图像条件配乐 | `lyria-3-pro-preview` | 时长受提示词影响，最长约三分钟；当前 $0.08/次 |
| 实时、持续可控的器乐演奏 | `lyria-realtime-exp` | 独立 WebSocket 工作流；勿经 `google_music` 路由 |

当前 OpenMontage 的 `google_music` 适配器固定为 `lyria-3-pro-preview`。它不暴露 Clip、WAV 响应选择、多图或 RealTime 控制。应明确说明该限制，勿暗示这些选项可通过适配器使用。

勿静默更换模型。针对 30 秒视频，要么获得 Pro 加精确时长母版处理的批准，要么通过明确支持的路径使用 Clip。

## 构建提示词

按以下顺序说明：

1. **用途与时长** — 音乐所支撑的内容及请求长度。
2. **流派与年代** — 使用音乐术语，勿模仿在世艺人。
3. **速度与和声** — BPM 或速度范围、拍号、调性或 tonal center（调性中心）。
4. **配器与质感** — 点明主奏、节奏、低音与环境层。
5. **结构** — 带时间戳的段落或 `[Intro]`、`[Verse]`、`[Chorus]`、`[Bridge]`、`[Outro]`。
6. **力度与同步** — 与剪辑时间对齐的进入、休止、渐强、重音与保持。
7. **人声策略** — 仅器乐约束、人声画像，或清晰分隔的自定义歌词。
8. **混音与结尾** — 密度、前景/背景角色、余量（headroom）特征与最终衰减。
9. **排除项** — 不需要的人声、乐器、手势、陈词滥调、突兀结尾或受版权保护素材。

针对视频铺底，使用时间戳窗口覆盖完整请求时长。每个窗口要求一项主要变化，并标明精确同步时刻。

针对仅器乐输出，在相关时须同时说明：

```text
Instrumental only. No lead or backing vocals, speech, choir, humming,
vocal chops, spoken samples, lyrical fragments, or recognizable quotations.
```

自定义歌词时，在单独的 `Lyrics:` 块之前写表演方向，并使用段落标签。提示词使用歌手应使用的语言。

## 规划人声

当需要人声时，在写提示词前先定义：

1. **人声角色** — 独唱主声、二重唱、一呼一应（call-and-response）、背景和声或人声质感。
2. **语言与文字** — 标明演唱语言，自定义歌词保持单一既定文字体系；勿静默转写或混用语言。
3. **歌手画像** — 声部或音域、音色、强度、咬字、装饰与情感距离。勿模仿具名艺人。
4. **段落行为** — 说明主声进入位置、和声或回声出现位置，以及哪些段落保持器乐。
5. **歌词契约** — 将方向与 `Lyrics:` 块分开，使用 `[Verse]`、`[Chorus]`、`[Bridge]`、`[Outro]`，括号仅用于有意的背景和声回声。

在试听前将返回的人声视为不可信。检查歌词贴合度、语言漂移、发音、可懂度、多余的背景和声、人声/乐器平衡，以及表演是否遵循请求的情感弧线。技术上有效但咬字差或歌词被改的文件不算批准的人声结果。

## 在探测前将时长视为不可信

Lyria 3 Pro 时长通过提示词指令与时间戳控制，而非精确 API 参数。OpenMontage 适配器会追加目标时长指令，但其返回的 `duration_seconds` 字段是请求值，而非媒体探测结果。

始终检查生成文件：

```bash
ffprobe -v error -show_entries \
  format=duration,format_name,bit_rate:stream=codec_name,sample_rate,channels \
  -of json output.mp3
```

若需要精确时长：

- 保持提供商源文件原样不动；
- 分别记录请求时长与实测时长；
- 在音乐上合理的边界处裁剪并加短淡出，导出新的母版；
- 未经批准的制作方案勿拉伸、循环或重新生成；
- 记录衍生过程并再次探测母版。

## 安全认证与诊断

Gemini API 通常使用 `GEMINI_API_KEY`。OpenMontage 还支持 `GOOGLE_API_KEY` 与 Vertex 服务账号凭据。

- 每次运行只使用一条已知凭据路径。
- 调试时勿打印密钥或编辑凭据文件。
- 勿假设被拒绝的第一把密钥会自动回退到第二把已配置密钥。
- 在当前 OpenMontage 解析器中，当两者均非空时 `GOOGLE_API_KEY` 优先于 `GEMINI_API_KEY`。
- 将 `403`、`API_KEY_SERVICE_BLOCKED` 及项目/服务限制视为认证或 Google 项目配置失败，而非提示词质量问题。
- 权限失败勿消耗重试次数。先解决凭据/项目路径。
- 仅在批准的重试与预算策略内对短暂限流或超时失败重试。

## 解析并记录结果

优先使用 `interaction.output_audio`。对交错响应，遍历 `model_output` 步骤并选取音频块；若歌词或结构描述相关，单独捕获输出文本。

记录：

- 提供商与确切模型；
- 原始提示词及任何图像来源信息；
- 请求时长与探测时长；
- 实际 codec、采样率、声道与文件路径；
- 单次费用与总尝试次数；
- 是否请求人声及试听是否检测到人声；
- 提供商源文件及任何单独导出的制作母版。

## 质量检查清单

- 提示词说明用途、速度、乐器、结构、力度、人声策略与结尾。
- 时间戳窗口覆盖预期时长且无矛盾。
- 未请求模仿特定艺人或受版权保护歌词。
- 输出文件存在、非空、可解码且含音频流。
- 实际时长与技术属性来自探测，而非请求元数据。
- 器乐输出检查是否意外含人声素材。
- 试听开头、同步时刻、过渡与结尾。
- 未改动的源文件已保留，任何制作母版有明确来源追溯。
- 在来源追溯重要处承认 SynthID 水印与预览模型不稳定性。
