# 步骤 2：策略与信息传达

**首先浏览 [capabilities.md](capabilities.md) 中的目录** — 24 行的目录表概括了 HyperFrames 能做什么。你需要据此向用户说明可能性。仅当某个节拍需要时再深入阅读具体章节。

你已完成站点采集，并已理解品牌 — 产品做什么、面向谁、用什么语气说话、整体氛围如何。在做任何创意决策之前，**先与用户对齐这支视频要讲述的故事。** 已采集的资产是你在步骤 3 后期会动用的品牌工具箱；本步骤的对话重点不是这些资产。

**先解析用户的提示。** 读他们已经告诉你的内容 — 视频类型、风格、具体需求、时长。只问他们**没有**说明的事。若用户说「产品演示，展示看板和聊天，节奏适中」— 简报多半已经齐了。他们明明说了「产品演示」，就不要再问「要什么类型的视频？」。

跳过用户已回答的问题。只问缺什么。若提示已足够详细可直接开工，用一条消息确认方向后进入步骤 3。目标是补全缺口，不是盘问。

## 要问什么

在问用户任何问题之前，先扎根于品牌：快速浏览步骤 1 刚写好的 `DESIGN.md`（颜色 / 字体 / 语气）；阅读 `capture/extracted/asset-descriptions.md` 了解有哪些视觉资产；快速浏览 `capture/extracted/visible-text.txt` 看站点如何自述。不要把全部内容复述给用户 — 那是噪音；他们刚采集过站点，知道有什么。用这些信息起草一段紧凑的品牌 framing，再进入问题。

用下面的问题与用户互动。若你的 agent 有多选/自定义选项的问答 UI，优先使用；否则以对话方式提问。

### 问题 1：这支视频是做什么的？

根据已采集站点给出合理选项：

**示例（非必选列表）**

- **社交广告**（15–20 秒）— Instagram、TikTok、LinkedIn。快、狠、前 2 秒要有钩子。
- **产品演示**（30–60 秒）— 走查核心功能。旁白、专业感。
- **发布预告**（15–25 秒）— 为新功能或产品造势。戏剧化揭晓。
- **品牌片**（20–45 秒）— 展示品牌识别。视觉主导、旁白极少。
- **功能公告**（15–30 秒）— 突出某一功能或更新。
- 或描述其他类型。

这决定时长、节拍数量、旁白密度和整体能量。

### 问题 2：什么风格 / 氛围？

请用户描述期望 — 或对**描述动效与能量**的具体 framing 做出反应，而不是 aesthetic 预设菜单。

**不要**呈现带预填说明的风格标签菜单（例如「电影感 = 暗色 + 光晕 + Apple  keynote 能量」）。那些说明会变成简报，即使与品牌不符。「电影感」对 wellness 品牌与对安全工具应完全不同 — 但带 baked-in 描述的标签会抹平这种差异。

改为用 approachable 的开放式问题：

> 「几个问题把方向定准：
>
> - **节奏：** 视频要慢、让画面呼吸，还是快、有冲击力？或介于两者之间？
> - **氛围：** 你希望观众感受到什么 — 暗而戏剧、干净明亮、活力四射，还是别的？
> - **旁白：** 需要声音引导观众，还是纯视觉叙事？
> - **有没有特别想要的？** 任何时刻、手法或参考？也可以说「你看着办」，我会基于采集结果发挥。」

他们的回答会修改你在步骤 1 建立的品牌基线。当用户表述与品牌冲突时，不要盲覆盖 — 让品牌与用户方向收敛。若冲突明显（用户要「暗色电影感」而品牌全是白与 pastel 的轻量感），先点出并询问再定夺。

### 问题 3：这支视频必须传达的**唯一**信息是什么？

这是策略问题。有效的营销视频都有一个核心信息 — 必须让观众记住的那一点。每个节拍要么服务这一点，要么不该出现。在谈视觉、资产或具体场景之前，先让用户说清这一点。

可以这样 framing：

> 「根据站点，我目前的品牌框架是：
>
> - **产品做什么：** [站点摘要里的一句话 — 不是功能列表，而是实际解决的 job]
> - **受众：** [面向谁，来自文案与视觉调性]
> - **品牌语气：** [自信 /  playful / 临床 / 紧迫 / 高端 — 品牌说话的调子]
>
> 在规划视觉之前，两个问题锚定故事：
>
> 1. **这支视频必须传达的唯一信息是什么？** 若观众看完后只记住一句，应是哪句？（价值主张、发布宣告、某功能主张、品牌感受、问题-解决方案对等）
> 2. **叙事形状是什么？** 可能弧线：_问题 → 解决方案_（多数 demo）、_揭晓_（发布、预告）、_演示_（功能展示、 walkthrough）、_氛围片_（品牌片 — 感受重于信息）、_对比_（对竞品 / 前后对比）。可选或自拟。
>
> 你可以直接给答案，也可以说「你看着办」，我会结合品牌与问题 1（[视频类型]）来定。」

有了答案之后，**再**勾勒以合成场景为先的节拍方向 — 但每条都要锚定在信息与弧线上，而不是资产清单：

> 「结合 [核心信息] 与 [叙事弧线]，我会这样 shaping：
>
> - [基于问题 1 答案的合成优先草图，例如：「用 kinetic typography 开场点出痛点 —『你每周在 context switch 上浪费 4 小时。』切到合成看板，卡片从混乱动画归入有序列。结尾品牌 mark + tagline。」]
> - [不同弧线的备选草图，例如：「揭晓弧线：暗色 canvas → 粒子汇聚 → 首个功能落下时产品 wordmark 逐笔绘制。无问题陈述 — 纯公告能量。」]
> - [若用户要 demo：「三块合成 UI 面板 — 看板、AI 聊天、command palette — 各用品牌 palette，左上角 stamp 品牌 logo。旁白逐段讲解。结尾 hold wordmark。」]
>
> 可叠加的品牌 accent：[列出 1–3 个*可能*入镜的采集资产：片头/片尾 SVG logo、某场景 hero 插画作景深层、gradient 图作 ambient 背景 wash。注明为候选而非定案 — 多数节拍用不到。]"

**重要：** 每个方向先讲**节拍传达什么**，再讲**如何构建**（哪些 primitives）。窄规则：若第一反应是「产品 UI 截图飞入」，请翻转 — 用 div 与 CSS  compose UI。这正是本 skill 要打破的 slideshow 模式。采集到的 logo、插画与 hero 图无需翻转 — 概念需要时它们是合法的主视觉。

采集资产是你在分镜后期才动用的品牌工具箱，服务于概念 — 绝不能作为概念的起点。

提供选项：

- **我有具体想法** — 让我描述
- **你看着办** — 你做创意决策，我审分镜
- **先看几个方案** — 提出 2–3 个创意方向我来选

### 问题 4：旁白？

不是每支视频都需要旁白。询问：

- **要旁白** — 声音引导观众（多数产品 demo、发布预告、功能公告）
- **不要旁白，纯视觉** — 仅音乐/音效，画面讲故事（品牌片、社交广告、音乐驱动片）
- **极简旁白** — 仅一句 hook 或 tagline，其余靠视觉（短社交广告、预告）

此决定改变流水线：

- **有旁白：** 步骤 3 含完整脚本。步骤 4 生成 TTS、转写、将时间戳映射到节拍。
- **无旁白：** 步骤 3 无脚本（分镜中 VO 提示为空）。跳过步骤 4 — 在分镜中按节奏与 pacing 手动规划节拍时长。

### 问题 5（如适用）：画幅？

仅当用户未指定时询问：

- **横屏**（1920×1080）— YouTube、LinkedIn、网站嵌入（默认）
- **竖屏**（1080×1920）— Instagram Stories、TikTok、YouTube Shorts
- **方屏**（1080×1080）— Instagram 信息流、Twitter/X

## 如何处理回复

### 「你看着办」/ 方向极少

用户几乎不给创意方向时，默认采用品牌视觉识别与视频用途所暗示的方向。在默认之前，你至少需要的最小上下文：**视频将在哪出现**（社交 feed / 落地页 / pitch deck / TV 广告）以及**面向谁**（开发者 / 消费者 / 企业 / 泛受众）。若缺任一项，问一次 —「会在哪播、给谁看？」— 然后继续。

有了最小上下文，仍应写 ambitious 的分镜。「你看着办」意思是「给我惊喜」，不是「保守安全」。大胆一点。

**自主模式会向下传递 — 仅针对用户偏好类关卡。** 当用户在此步骤 2 表示「你看着办 / 替我定 / 直接做」时，该信号会关闭下游用户偏好 💬 关卡：步骤 3 分镜审批、步骤 4 TTS 提供商选择、要不要音乐、要不要字幕。这些创意决策由你做出，最后呈现成片。不要在四个步骤里问四个独立问题。读一次 room 并 commit。

**自动模式不会跳过质量验证关卡。** 无论何种模式都必须运行，并在最终摘要中留下证据：

- 资产审计（步骤 3）— 查看 contact sheets，逐资产说明 USE/SKIP 理由
- 每节拍 HTML 证据块（步骤 5）
- DoD 清单（步骤 6）— animation-map、逐 warning 的 WCAG 验证、音频与动效播放（或明确「deferred」披露）
- 「我未验证的内容」披露（步骤 6）

**「偏好 vs 质量关卡」测试：** 若答案会改变视频**内容**（哪个声音？开字幕？第 3 节拍电影感还是快节奏？），属于偏好 — 自动模式决定。若答案是「验证有没有做？」，属于质量关卡 — 自动模式不适用。以「自动模式说要行动 bias，所以我跳过 contact sheets」来推理是误用自动模式。

### 具体方向

若表述模糊（「做得酷一点」），温和 push back：

> 「我想确保命中你的想象。你说『酷』 — 是指：戏剧/电影感（慢揭晓、暗氛围）？还是高能量（快切、 bold 动效）？还是完全不同的东西？」

### 混合方向

逐条解析。「极简但电影感转场、功能段要快」可变为：

- **基础风格：** 极简（适中 pacing、minimal density、elegant motion）
- **转场 override：** 戏剧化（关键 moment 用 shader 效果）
- **节拍 3–5 override：** 快 pacing、balanced density、energetic motion

记下这些 per-beat override — 写入分镜。

### 「先看几个方案」

提出 2–3 个简短创意方向（各 3–4 句），**叙事弧线**不同 — 视频讲什么故事，而不是展示什么资产。每个选项先 lead 信息与弧线；视觉是服务它们的 compose 场景。

> **方案 A — 问题 → 解决方案（电影感、有旁白）：** 开场用 kinetic typography 在暗 canvas 上陈述问题，单一 accent glow。切到 compose 的看板，混乱卡片动画归入有序列，旁白落地价值主张。结尾：品牌 mark 在品牌 gradient 的 shader bloom 上 stroke-by-stroke 绘制。Apple-keynote  register。~25s，完整 VO。
>
> **方案 B — 揭晓弧线（公告、音乐主导）：** 冷开场：黑暗中粒子汇聚，无文案。产品 wordmark 随第一拍 stroke 自绘横跨画面。三个 compose 功能面板以 hard cut 揭晓 — kinetic typography 标签、品牌色 wash、无截图。结尾 mark + tagline + macOS hint。~15s，音乐驱动，旁白极少。
>
> **方案 C — 演示（旁白 walkthrough）：** 三个 compose UI 场景 — 卡片即 div 的看板、与 typewriter 旁白同步的 AI 聊天、字符输入搜索的 command palette — 各用品牌 palette，采集 logo 左上角 stamp 作识别。CSS crossfade 衔接。旁白逐段讲解。~35s，完整 VO。

每个选项说明：弧线、承载它的主视觉（compose 或采集 — 视节拍而定）、以及叠在上面的品牌 accent。**绝不**以粘贴的产品 UI 截图为主内容的选项 — 若你在写这种，请翻转：说明改为 compose 什么。概念需要时，采集的 SVG、插画、hero 与品牌摄影可作为主视觉。

让用户选一个或组合元素。

## 关卡

进入步骤 3 前锁定以下全部。前三项是步骤 3 构建分镜的策略框架 — 没有它们，分镜无法落地。

1. **信息（Message）** — 这支视频必须传达的唯一信息，一句话。（必填。没有则步骤 3 失败。）
2. **叙事弧线（Narrative arc）** — 问题→解决方案 / 揭晓 / 演示 / 氛围 / 对比 / 自定义。（必填。）
3. **受众（Audience）** — 谁在看、在哪看。（必填。）
4. **视频类型** — 社交广告 / 产品 demo / 发布预告 / 品牌片 / 功能公告等。可从 prompt 推断。
5. **时长** — 未说明则按类型推断（demo：30–45s，社交：15–20s，预告：15–25s）。
6. **风格方向** — 节奏 / 氛围 /  specifics — 来自用户表述，叠在步骤 1 品牌基线上。
7. **具体请求** — 用户明确要求的场景/效果/节拍。
8. **旁白** — 要 / 不要 / 极简。
9. **画幅** — 默认横屏，除非另有说明。

**不要请用户确认他们已经说过的话。** 若 prompt 是「为 huly.io 做产品 demo，展示看板，暗色电影感，完整旁白」— 你已有类型（demo）、风格（暗色电影感）、具体请求（看板）、旁白（完整）。仍需推导或询问：**信息**（「为讨厌 context switch 的团队做的一切 app」）、**弧线**（演示）、**受众**（小团队 / 快节奏组织）。九项全部锁定后再进入步骤 3。
