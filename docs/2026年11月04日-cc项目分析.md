⏺ 结论：按层混合，并非“全本地”或“全云端”

  ┌──────────────┬───────────┬──────────────────────────────────────────────┐
  │   成片元素   │ 生成位置  │                     说明                     │
  ├──────────────┼───────────┼──────────────────────────────────────────────┤
  │ 最终视频帧   │ 始终本地  │ Remotion / HyperFrames / FFmpeg              │
  │              │           │ 在本机渲染、混音、编码                       │
  ├──────────────┼───────────┼──────────────────────────────────────────────┤
  │ 画面素材     │ 本地或云  │ 云端图像/视频 API、本地 GPU                  │
  │              │ 端        │ 模型、免版税素材库、程序化图形               │
  ├──────────────┼───────────┼──────────────────────────────────────────────┤
  │ 配音         │ 本地或云  │ tts_selector 自动路由；Piper                 │
  │              │ 端        │ 是本地离线方案，云端 TTS 可选                │
  ├──────────────┼───────────┼──────────────────────────────────────────────┤
  │ 背景乐       │ 本地或云  │ 用户曲库 → 免版税搜索 → 音乐生成（云端/本地  │
  │              │ 端        │ ComfyUI）→ 明确不可用                        │
  ├──────────────┼───────────┼──────────────────────────────────────────────┤
  │ 混音/字幕/封 │ 始终本地  │ audio_mixer、video_compose、remotion_caption │
  │ 装           │           │ _burn                                        │
  └──────────────┴───────────┴──────────────────────────────────────────────┘

  一句话：素材可以上云，成片渲染一定落在本地。

  1. 视频帧要拆成两层

  第一层：源素材帧（画面内容从哪来）

  - 云端 AI 图像：image_selector 路由到
    flux_image、google_imagen、openai_image、seedream_image、recraft_image 等。
  - 本地 AI 图像：local_diffusion（diffusers，本地 GPU）、comfyui_image（本地
    ComfyUI 服务）。
  - 云端 AI 视频：video_selector 路由到 kling_video、veo_video、runway_video、se
    edance_video、sora_video、minimax_video 等，返回 MP4 片段。
  - 本地 AI 视频：wan_video、hunyuan_video、cogvideo_video、ltx_video_local、com
    fyui_video，需要 GPU、权重和较长推理时间。
  - 真实素材：Pexels、Pixabay 需免费
    Key；Archive.org、NASA、Wikimedia、NOAA、ESA、JAXA 等通过 direct_clip_search
    检索，多数无需 Key。
  - 程序化图形：Remotion
    场景组件（text_card、bar_chart、line_chart、kpi_grid、terminal_scene
    等）、HyperFrames HTML/CSS/GSAP、diagram_gen、code_snippet、math_animate、th
    reejs_world，由本地代码确定性生成。

  第二层：成片帧（最终 MP4 的画面）

  - Remotion：React 组件用 useCurrentFrame() / interpolate() / spring()
    计算每一帧，npx remotion render 在本地 headless Chromium 渲染，FFmpeg
    编码并混音。
  - HyperFrames：HTML/CSS/GSAP 时间线在本地 headless 浏览器播放并逐帧捕获，npx 
    --yes hyperframes render 调用本机 FFmpeg 编码。
  - FFmpeg：filter graph 完成拼接、裁剪、缩放、字幕烧录、混音和最终编码。

  即使整条片子只有一个云端 AI
  视频片段，也要在本地完成下载、时间线组装、混音、字幕/封装和重新编码。云端视频 
  API 提供的是素材片段，不是成片。

  2. 配音：tts_selector 路由，Piper 兜底

  项目没有硬编码的默认 TTS。tts_selector 自动发现所有 capability="tts"
  的工具，按可用性 + 七维加权打分（任务匹配、质量、控制力、可靠性、成本、延迟、
  连续性）选择，preferred_provider 可覆盖。

  - 本地：piper_tts，runtime=LOCAL，依赖
    cmd:piper，完全离线、免费、无网络请求；音质不如云端神经语音。
  - 云端：ElevenLabs、Google、OpenAI、Azure、Cartesia、Fish
    Audio、Inworld、Mistral、Kling、DashScope、豆包、Grok、HeyGen 等，需要各自
    Key。

  生产时 asset-director 按 script 的每个 section 生成一段旁白到
  projects/<id>/assets/narration/，先做样本给用户试听，确认后才批量生成；最后由
  audio_mixer 做 ducking、淡入淡出和 loudnorm（默认 -16 LUFS）。

  字幕方面，供应商支持词级时间戳时直接使用；不支持时可用本地
  transcriber（faster-whisper / WhisperX）对齐。词级高亮由 Remotion 的
  CaptionOverlay / remotion_caption_burn 完成；HyperFrames
  目前不支持词级字幕，需要时必须在 proposal 锁定 render_runtime="remotion"。

  3. 背景乐：先定来源，再落地

  背景乐没有 music_selector，因为它涉及版权、情绪、时长和用户偏好。Proposal
  阶段按顺序确认：

  1. 用户已选中的 music_library/ 曲目；
  2. 本地 music_library/ 扫描，按 audio.music_mood 列候选；
  3. 免版税搜索：freesound_music（需 Key）、pixabay_music（无需
     Key，网页抓取）；
  4. 音乐生成：music_gen（ElevenLabs）、suno_music、google_music（Lyria）、fal_e
     levenlabs_music、elevenlabs_soundtrack、comfyui_music（本地 GPU）；
  5. 都没有：明确告诉用户，并建议先把曲子放进 music_library/。

  失败时必须在 asset_manifest 写 "music_status": "unavailable"
  和原因，不能静默输出无音乐视频。

  4. 零 Key 能做到什么？

  零 Key 可以完成：Piper 配音（需装 piper）、Remotion/HyperFrames/FFmpeg
  程序化动画、本地文件与部分公共档案素材。但 AI 图像/视频生成要么需要云端 
  Key，要么需要本地 GPU 模型；Pexels/Pixabay 也需要免费 Key。所谓“零 Key
  演示”通常是程序化场景 + 本地素材，不是任意 AI 画面。

  1. Piper

  作用

  把文本合成为本地语音，适合离线、隐私敏感、零 API 费用的旁白。OpenMontage
  用它作为 tts_selector 的本地兜底。

  原理

  1. 文本先由 espeak-ng 转成音素。
  2. 音素输入 VITS 声学模型（约 15M 参数），端到端生成波形。
  3. 模型导出为 ONNX，由 onnxruntime 在 CPU 推理；可选 onnxruntime-gpu。
  4. 支持多说话人、语速 --length-scale、句间停顿 --sentence-silence。
  5. 输出采样率：x_low/low 为 16 kHz，medium/high 为 22.05 kHz。

  本地资源消耗

  ┌──────┬──────────────────────────────────────────────────────────┐
  │ 项目 │                           数值                           │
  ├──────┼──────────────────────────────────────────────────────────┤
  │ CPU  │ 1-2 核；Pi 4 建议 low，Pi 5 可跑 medium                  │
  ├──────┼──────────────────────────────────────────────────────────┤
  │ 内存 │ 0.2-0.5 GB（项目 resource_profile 写 512 MB）            │
  ├──────┼──────────────────────────────────────────────────────────┤
  │ 显存 │ 0                                                        │
  ├──────┼──────────────────────────────────────────────────────────┤
  │ 磁盘 │ 0.1-0.3 GB；单个 voice 约 21-137 MB                      │
  ├──────┼──────────────────────────────────────────────────────────┤
  │ 网络 │ 仅首次下载 voice，推理完全离线                           │
  ├──────┼──────────────────────────────────────────────────────────┤
  │ 速度 │ 桌面 RTF ≈ 0.15-0.2，约 5-6.5× 实时；Pi 5 短句约 0.54 秒 │
  └──────┴──────────────────────────────────────────────────────────┘

  2. Manim

  作用

  Python 程序化数学/技术动画引擎，用代码描述公式、几何、函数曲线和 3D
  场景。OpenMontage 的 math_animate 调用本机 manim CLI 生成数学解释片段。

  原理

  1. 用户定义 Scene，组合 Mobject（圆、线、公式、文字等）。
  2. play() / animate 定义时间轴插值。
  3. 默认 Cairo renderer 用 pycairo 逐帧栅格化；可选 OpenGL renderer 用 GPU。
  4. 每帧交给 PyAV/FFmpeg 编码为 MP4；MathTex 通过 LaTeX + dvisvgm 生成公式。
  5. 支持 partial movie 缓存，但 OpenMontage 的 math_animate 传了
     --disable_caching，每次完整渲染。

  本地资源消耗

  ┌──────┬──────────────────────────────────────────────┐
  │ 项目 │                     数值                     │
  ├──────┼──────────────────────────────────────────────┤
  │ CPU  │ 1 核/场景；Cairo 单线程，多场景可并行进程    │
  ├──────┼──────────────────────────────────────────────┤
  │ 内存 │ 0.35 GB/1080p 进程起；系统建议 4-8 GB        │
  ├──────┼──────────────────────────────────────────────┤
  │ 显存 │ 0（Cairo）；OpenGL renderer 可选 GPU         │
  ├──────┼──────────────────────────────────────────────┤
  │ 磁盘 │ 库约 0.5 GB；项目 5 GB+；TeX Live 另需 5 GB+ │
  ├──────┼──────────────────────────────────────────────┤
  │ 网络 │ 首次装依赖，渲染离线                         │
  ├──────┼──────────────────────────────────────────────┤
  │ 速度 │ 简单 2D 近实时；3D/光照 20-40× 实时          │
  └──────┴──────────────────────────────────────────────┘

  1080p60 第三方实测（M4 Pro，ManimCE 0.21.0）：

  - 2D 矩阵 7.2 秒视频 → 7.1 秒；
  - 12 单摆 13 秒 → 4.7 秒；
  - 3D 行星层级 3 秒 → 16.2 秒；

  - 3D 曲面+轨道相机 10 秒 → 211.8 秒。

  - $0 许可费；成本是 CPU 时间、内存、磁盘和 LaTeX。
  - MathTex/Tex 需要 LaTeX + dvisvgm；只用 Text 可以不装完整 TeX。

  注意

  OpenMontage math_animate 有 300 秒超时，1080p60/4K
  复杂场景很容易超时；建议先用 low/medium 出草稿，再分段渲染。

  3. Mermaid CLI

  作用

  把 Mermaid DSL（flowchart、sequenceDiagram、classDiagram、ER、gantt 等）渲染成
  SVG/PNG/PDF。OpenMontage 的 diagram_gen 用它生成流程图、架构图、关系图。

  原理

  1. mmdc 解析 .mmd 文本，生成 Mermaid AST。
  2. Mermaid 在浏览器中完成布局（Dagre/ELK）并生成 SVG。
  3. mmdc 通过 Puppeteer 启动 headless Chromium，加载 Mermaid bundle 渲染。
  4. SVG 是矢量输出，最适合视频合成；PNG/PDF 再截图/打印。
  5. 主题、字体、CSS、透明背景可通过配置控制。

  本地资源消耗

  │ 项目 │                            数值                             │
  ├──────┼─────────────────────────────────────────────────────────────┤
  │ CPU  │ 1 核；解析本身很轻，Chromium 启动占大头                     │
  ├──────┼─────────────────────────────────────────────────────────────┤
  │ 内存 │ 0.1-0.3 GB；每个 Chrome 实例约 50-100 MB                    │
  ├──────┼─────────────────────────────────────────────────────────────┤
  │ 显存 │ 0                                                           │
  ├──────┼─────────────────────────────────────────────────────────────┤
  │ 磁盘 │ 0.3-0.5 GB（Node 模块 + Chromium 约 170-400 MB）            │
  ├──────┼─────────────────────────────────────────────────────────────┤
  │ 网络 │ 首次安装，渲染离线                                          │
  ├──────┼─────────────────────────────────────────────────────────────┤
  │ 速度 │ 2-3 秒/图；Chromium 启动 1-2 秒；共享浏览器可降到约 1 秒/图 │

  作用

  3. wav2vec2 强制对齐把时间戳细化到词级。
  4. 可选 pyannote 说话人分离，给每个词/段分配 speaker label。
  5. 输出 JSON：segments、words（start/end/probability）、speakers。

      1815 +### 16.4 视频（源视频 / 镜头素材）                           
      1816 +                                                             
      1817 +#### 16.4.1 作用                                             
      1818 +                                                             
      1819 +这里的“视频”指**源镜头**，不是最终成片。它的作用包括：       
      1820 +                                                             
      1821 +- **B-roll**：用实拍或生成画面覆盖旁白，避免全程“PPT 感”。   
      1822 +- **生成镜头**：拍不到、买不到、画不出来的画面（历史场景、科 
           +幻概念、微观过程）。                                         
      1823 +- **转场与节奏**：用运动镜头打破静态图文的节奏。             
      1824 +- **一致性**：用图生视频（I2V）把同一角色/产品/场景延续到多个
           +镜头。                                                       
      1825 +                                                             
      1826 +在 OpenMontage 里，`video_selector` 会自动发现所有 `video_gen
           +eration` 能力的工具，按任务上下文做 7 维加权评分；`asset-dire
           +ctor` 也可直接指定 `preferred_tool`。**不是每个场景都需要视频
           +**——信息型讲解视频里，动态图形、图表、代码片段往往比 AI 视频 
           +更清晰、更便宜。                                             
      1827 +                                                             
      1828 +#### 16.4.2 原理                                             
      1829 +                                                             
      1830 +当前主流文生视频/图生视频模型基本是 **Diffusion Transformer（
           +DiT）+ 3D VAE** 的组合：                                     
      1831 +                                                             
      1832 +```text                                                      
      1833 +文本 prompt                                                  
      1834 +   ↓ 文本编码器（T5 / CLIP / 多模态 LLM）                    
      1835 +条件向量                                                     
      1836 +   ↓                                                         
      1837 +随机噪声 latent（形状：帧数 × 分辨率/8 × 分辨率/8 × 通道）   
      1838 +   ↓ DiT 反复去噪 N 步（每步都做时空注意力）                 
      1839 +干净 latent                                                  
      1840 +   ↓ 3D VAE 解码                                             
      1841 +逐帧 RGB                                                     
      1842 +   ↓ 编码                                                    
      1843 +.mp4                                                         
      1844 +```                                                          
      1845 +                                                             
      1846 +关键机制：                                                   
      1847 +                                                             
      1848 +| 机制 | 作用 |                                              
      1849 +| --- | --- |                                                
      1850 +| 3D VAE / 时空压缩 | 把视频压到 latent 空间，降低计算量；时 
           +间维压缩让模型能处理多帧 |                                   
      1851 +| 时空注意力 | 同时建模“画面内空间关系”和“帧间运动” |        
      1852 +| 文本/图像条件 | 文生视频用 prompt；图生视频用首帧或参考图锁
           +定主体和风格 |                                               
      1853 +| 运动先验 | 模型在大量视频上学会了镜头运动、物体运动、物理常
           +识 |                                                         
      1854 +| 音频分支 | Veo 3、Kling 3、LTX-2 等支持原生音频/对白，省掉 
           +后期配音口型对齐 |                                           
      1855 +| 首尾帧/关键帧 | 用首帧、尾帧或中间关键帧控制镜头起止，适合 
           +做转场和连续性 |                                             
      1856 +                                                             
      1857 +**为什么一次只生成 5–10 秒？** 因为计算量随时长线性增长，而 l
           +atent 的时空注意力是平方级；再加上长视频容易出现主体漂移、物 
           +理崩坏。工程上的做法是“短片段生成 + 拼接/关键帧衔接”，而不是 
           +追求一次生成几分钟。

      1917 +### 16.5 配音（Voiceover / TTS）                             
      1918 +                                                             
      1919 +#### 16.5.1 作用                                             
      1920 +                                                             
      1921 +- **把脚本变成可听的旁白**：每个 `section` 生成一条音轨，按时
           +间码拼接。                                                   
      1922 +- **承载表演**：语速、停顿、重音、情绪决定视频的“人味”；`voic
           +e_performance` 和 `delivery_cues` 就是为此设计的。           
      1923 +- **对齐字幕**：TTS 的时长和词级时间戳是字幕、口型、画面切换 
           +的依据。                                                     
      1924 +- **多语言/多音色**：同一脚本可以生成不同语言、不同性别、不同
           +年龄的版本。                                                 
      1925 +- **品牌一致性**：固定音色（voice ID）让系列视频听起来像同一 
           +个主持人。                                                   
      1926 +                                                             
      1927 +#### 16.5.2 原理                                             
      1928 +                                                             
      1929 +TTS 的经典三段式：                                           
      1930 +                                                             
      1931 +```text                                                      
      1932 +原始文本                                                     
      1933 +  ↓ 文本前端：清洗、断句、数字/单位/缩写展开、G2P（字素→音素 
           +）、韵律预测                                                 
      1934 +音素序列 + 韵律标注                                          
      1935 +  ↓ 声学模型：VITS / Flow Matching / Diffusion / 自回归 Trans
           +former / 神经编解码语言模型                                  
      1936 +梅尔频谱或离散声学 token                                     
      1937 +  ↓ 声码器：HiFi-GAN / BigVGAN / 神经编解码解码器            
      1938 +波形 PCM → WAV / MP3                                         
      1939 +```                                                          
      1940 +                                                             
      1941 +不同路线的差异：                                             
      1942 +                                                             
      1943 +| 路线 | 代表 | 特点 |                                       
      1944 +| --- | --- | --- |                                          
      1945 +| 端到端 VITS | Piper | 轻量、快、CPU 可实时；音色靠训练好的 
           +voice，不能零样本克隆 |                                      
      1946 +| Flow Matching | F5-TTS、CosyVoice 2 | 质量高、支持零样本克 
           +隆、可控韵律；需要 GPU |                                     
      1947 +| Diffusion | 部分高保真 TTS | 质量最好，但推理步数多、慢 |  
      1948 +| 自回归 / 神经编解码 | Fish Speech、CosyVoice 2、ChatTTS |  
           +自然度和表现力强，支持克隆；延迟和稳定性要调 |               
      1949 +| 云端大模型 TTS | ElevenLabs、OpenAI、Google、Azure | 免运维
           +、音色多、支持 SSML/情感指令；按字符或分钟计费 |             
      1950 +                                                             
      1951 +**零样本克隆**的原理：用一段 3–30 秒的参考音频提取说话人嵌入 
           +（speaker embedding）或声学 prompt，条件化到声学模型中，不需 
           +要为每个人重新训练。代价是克隆质量高度依赖参考音频的干净程度 
           +，且涉及声音人格权/版权，商用要谨慎。                        
      1952 +                                                             
      1953 +**时长控制**：`length_scale`（Piper）或 `speed`（云端 TTS）可
           +以整体缩放语速；`pause_before_seconds` / `pause_after_seconds
           +` 在段落间插静音；SSML 的 `<break>` 可以精确控制停顿。OpenMon
           +tage 的 `script.sections[].delivery_cues` 就是把这些参数结构 
           +化。

      2106 +### 16.7 视频帧（最终渲染）                                  
      2107 +                                                             
      2108 +#### 16.7.1 作用                                             
      2109 +                                                             
      2110 +- **把时间轴变成像素**：所有脚本、图像、视频、字幕、动画、音 
           +频，最终都要在这里合成。                                     
      2111 +- **保证确定性**：同样的输入和渲染运行时，应该得到同样的输出 
           +；这是可复现、可审核的基础。                                 
      2112 +- **承载动画与排版**：文字动画、图表增长、转场、遮罩、粒子效 
           +果都在这一层完成。                                           
      2113 +- **烧录字幕/水印/片头片尾**：最终交付物的“最后一公里”。     
      2114 +- **输出多版本**：16:9 / 9:16 / 1:1、不同分辨率、不同码率。  
      2115 +                                                             
      2116 +#### 16.7.2 原理                                             
      2117 +                                                             
      2118 +```text                                                      
      2119 +edit_decisions（时间轴：轨道、片段、入点/出点、转场、特效）  
      2120 +        ↓                                                    
      2121 +选择 render_runtime（proposal 阶段锁定，不能静默替换）       
      2122 +        ↓                                                    
      2123 +逐帧渲染：frame N → 画面树 → 像素                            
      2124 +        ↓                                                    
      2125 +编码：H.264 / H.265 / ProRes，CRF/码率，fps                  
      2126 +        ↓                                                    
      2127 +封装：视频轨 + 音频轨（AAC）+ 字幕轨                         
      2128 +        ↓                                                    
      2129 +final.mp4                                                    
      2130 +```                                                          
      2131 +                                                             
      2132 +三种主流渲染路径：                                           
      2133 +                                                             
      2134 +| 运行时 | 原理 | 适合 |                                     
      2135 +| --- | --- | --- |                                          
      2136 +| **Remotion** | React 组件树描述每一帧；`useCurrentFrame()` 
           +拿到当前帧号；headless Chrome 逐帧截图；FFmpeg 编码 | 文字动 
           +画、数据图表、UI 演示、复杂排版 |                            
      2137 +| **HyperFrames** | HTML/CSS/GSAP 描述动画；headless 浏览器按
           +时间采样；FFmpeg 编码 | 网页风格动效、GSAP 时间轴、快速原型 |
      2138 +| **FFmpeg** | `filter_complex` 滤镜图：trim/concat/overlay/s
           +ubtitles/scale；无浏览器 | 剪辑、拼接、字幕、音频混合、批处理
           + |                                                           
      2139 +| **Manim** | Python 场景类逐帧渲染数学动画；Cairo 光栅化；FF
           +mpeg 编码 | 公式、几何、函数、算法可视化 |                   
      2140 +| **Blender / Three.js** | 3D 场景渲染；Blender 用 Cycles/Eev
           +ee，Three.js 用 WebGL | 3D 产品展示、空间场景 |

           +画、品牌元素 |                                               
      2142 +                                                             
      2143 +**帧数计算**：                                               
      2144 +                                                             
      2145 +```text                                                      
      2146 +总帧数 = 时长（秒）× 帧率（fps）                             
      2147 +5 分钟 @ 30 fps = 300 × 30 = 9,000 帧                        
      2148 +5 分钟 @ 60 fps = 300 × 60 = 18,000 帧                       
      2149 +```                                                          
      2150 +                                                             
      2151 +**为什么渲染比播放慢？** 播放时解码器只需要按时间解码；渲染时
           +每一帧都要重新计算画面树、布局、绘制、光栅化、编码。Remotion 
           +的每一帧相当于一次“无头浏览器截图”，所以 CPU 单核性能、内存带
           +宽、图片解码速度都比 GPU 更重要。                            
      2152 +                                                             
      2153 +**渲染运行时锁定**：OpenMontage 在 proposal 阶段就确定 `rende
           +r_runtime`（Remotion / HyperFrames / FFmpeg），后续不能静默换
           +。原因是不同运行时的字体、布局、动画曲线、编码参数不同，换了 
           +会导致成片风格不一致，也会让 `render_report` 无法复现。

  3. 配音（Voiceover / TTS）

  作用：把脚本变成可听旁白；承载语速、停顿、重音、情绪；词级时间戳用于字幕和画面

  4. 背景乐（BGM）

  作用：情绪定调、节奏驱动、掩盖剪辑缝、品牌识别、在关键结论处让位给旁白。

  原理：OpenMontage 有明确的来源优先级——用户指定 → 本地 music_library/ →
  音乐生成 API（music_gen / suno_music / google_music）→ 明确标记
  "music_status": "unavailable"，不会静默跳过。生成式音乐用文本/参考音频条件化
  Transformer / Diffusion 模型，输出 30 秒–4 分钟音频；混音阶段由 audio_mixer
  做循环、ducking（旁白出现时压低音乐）、淡入淡出、loudnorm（默认 -16 LUFS）。

  5. 视频帧（最终渲染）

  作用：把时间轴变成像素；承载动画、排版、图表增长、转场、遮罩、字幕烧录、片头片
  尾；输出 16:9 / 9:16 / 1:1 多版本；保证同样输入得到同样输出。

  原理：edit_decisions（轨道、片段、入点/出点、转场、特效）→ 选择
  render_runtime（proposal 阶段锁定，不能静默换）→ 逐帧渲染 →
  编码（H.264/H.265/ProRes）→ 封装音频和字幕。

  选型建议

  - 脚本：云端 LLM 看“一次过稿率”，本地 LLM 看隐私；无论用谁都要 JSON Schema
    校验 + 人工门。
  - 视频：库存优先，生成只用于“拍不到”的镜头；每个镜头 5–10 秒；不要在 AI
    视频里放文字/Logo/UI。
  - 配音：Piper 做草稿，云端 TTS 做成片；先做 sample 再批量；务必检查 voice
    许可证。
  - 背景乐：先扫 music_library/；需要定制情绪再生成；授权优先于价格；一定要做
    ducking 和 loudnorm。
  - 视频帧：本地 Remotion/HyperFrames 是默认答案；文字密集型视频不要用 AI
    视频生成；先低分辨率预览再出最终版；锁定 render_runtime；4K 按需。
